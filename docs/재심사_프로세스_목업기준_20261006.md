## 1. 전체 흐름

```
[학생] 논문신청 [관리] → 신청완료
   → [학생] 학위논문제출: N차 제출
   → [관리자] 심사위원 배정 · 일정 등록 (기존)
   → [교수] 심사위원 평가 → 위원장 판정
        ├ 합격 ─────── 단계 완료
        ├ 조건부합격 ── 같은 신청 안에서 N+1차 보완 제출 → 다시 심사
        └ 불합격 ───── (불합격 학기에는 다시 진행 불가)
              ├ 1안: 신청 유지 → 다음 학기 제출기간에 N+1차 제출
              └ 2안: 신청만 리셋(미신청, 심사 내역 보존) → 다음 학기 [관리]로 다시 신청 → N+1차 제출
```

## 2. 신청 철회와 제출취소 (별개 기능)

| | 신청 철회 | 제출취소 |
|---|---|---|
| 위치 | 논문신청 상세 [논문 신청 철회] (철회기간) | 학위논문제출 상세 [제출취소] (결과 전 + 제출기간) |
| 삭제 범위 | 신청과 그 신청의 제출 | **해당 차수(세부단계) 제출만** — 신청·이전 차수 기록 유지 |
| 불가 조건 | 같은 신청 안에 심사 내역(평가 저장, **임시저장 포함**) 또는 판정 결과 | 해당 차수에 심사 내역(임시저장 포함) 또는 판정 결과 → 심사중으로 간주 |
| 불가 문구 | "심사가 진행중이므로 철회할 수 없습니다." | "심사가 진행 중이어서 제출을 취소할 수 없습니다." |
| 확인 문구 | 제출 있음: "제출한 심사자료가 있습니다. 신청을 철회하면 제출 내역도 함께 삭제됩니다. 그래도 철회하시겠습니까?" / 없음: 요구서 문구 | "제출한 심사자료를 취소하시겠습니까? 제출한 파일이 삭제되며, 제출기간 내에 다시 제출할 수 있습니다." |
| 결과 | 미신청 ("논문 신청 내역이 초기화되었습니다.") | 해당 차수 미제출 ("제출이 취소되었습니다.") |

## 3. 재심사 1안 / 2안 (고객사 선택)

| | 1안: 신청 유지 | 2안: 신청 다시 |
|---|---|---|
| 불합격 후 신청상태 | 신청완료 | 미신청 (신청 내역만 리셋) |
| 다음 차수 | 다음 학기 제출기간에 같은 행에서 제출 | 다음 학기에 다시 신청 후 제출 |
| 장점 | 세부단계가 여러 개일 때 통과한 세부단계 심사 내역이 리셋되지 않음 | 재심사 의사를 신청으로 명시 |
| 고려 사항 | 불합격 후 신청 철회는 불가, 2차는 제출취소로 해당 차수만 되돌림 | 미신청인데 심사 내역이 남아 오류처럼 보일 수 있음 |

## 4. 화면별 요약

| 화면 | 동작 |
|---|---|
| 학생 논문신청 | 신청상태 미신청/신청완료, [관리] → 신청 모달 또는 신청 상세(철회) |
| 학생 학위논문제출 | 심사 건 1행, [제출]/[보기], 상세·제출 화면에 '1차 제출', '2차 제출'…, 상세 [제출취소](해당 차수만) |
| 교수 학위논문심사 | 심사 건 1행, [심사]/[승인] → 상세 위쪽 이전 차수 'N차 심사'(읽기 전용) |
| 관리자 | 기존 화면 그대로 조회, 학위논문심사 1행 + [상세보기]에서 이전 차수 조회, 철회·제출취소 기능 없음 |

## 5. 목업의 한계

1. 화면 간 데이터 연동 없음 — 학생 화면은 시연 바(시나리오 ①~⑥ + 재심사 안)로 상태를 재현
2. 기본단계당 세부단계가 1개라 '통과한 세부단계 보존'(1안 장점)은 화면에 표현되지 않음
3. DB View, 지도교수 변경 반영은 화면에 표현하지 않음
