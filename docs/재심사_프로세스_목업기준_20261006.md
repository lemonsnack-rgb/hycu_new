- 기준: 요구사항정의서 JXLB-1·2·7, `재심사_목업_재정비_계획_20261007.md`
- 목업: https://hycu-new.vercel.app (학생 `/student-v3/student-dashboard`, 교수 `/professor-v3/professor-dashboard-proposal`, 관리자 `/admin-v3`)
- 원칙: 명시된 요구사항만 구현, 기존 화면·버튼·상태값·용어 재사용, 관리자 화면은 조회만 하며 재심사 건을 따로 구분하지 않음

## 1. 전체 흐름

```
[학생] 논문신청 [관리] → 신청완료
   → [학생] 학위논문제출: N차 제출
   → [관리자] 심사위원 배정 · 일정 등록 (기존)
   → [교수] 심사위원 평가 → 위원장 판정
        ├ 합격 ─────── 단계 완료
        ├ 조건부합격 ── 다음 차수 심사 생성 → [학생] 신청 없이 N+1차 제출 → 다시 심사
        └ 불합격 ───── [학생] 신청상태 '재심사 진행' → [관리]로 다시 신청(동일·이후 학기) → N+1차 제출
```

- 이전 기본단계 결과는 영향 없음, 재심사 횟수 제한 없음 (요구서)
- 이전 차수의 제출 파일·평가·위원장 총평은 보존 (요구서)

---

## 2. 화면별 동작

### 2-1. 학생 — 논문 심사 > 논문신청 (기존 화면)

| 신청상태 | 조건 | 관리 버튼 |
|---|---|---|
| 미신청 (기존) | 신청 이력 없음 | [관리] → 기존 신청 모달 |
| 신청완료 (기존) | 신청함 | [관리] → 신청 상세 (기존 모달) — [논문 신청 철회]는 철회기간에만 |
| **재심사 진행** (요구서) | 불합격 확정 후 다시 신청하기 전 | [관리] → 기존 신청 모달로 다시 신청 |

**철회 (요구서, 신청 상세 화면에서)**
- 심사 진행 중(심사위원 1명 이상 평가)이거나 결과가 확정됐으면 "심사가 진행중이므로 철회할 수 없습니다."
- 그 외에는 "해당 단계에서 제출한 자료와 내역은 모두 초기화됩니다(합격여부가 결정된 단계 제외) 그래도 철회하시겠습니까?" 확인 후 철회
- 철회하면 신청과 제출 자료가 삭제되고 미신청(이전 불합격 기록이 있으면 재심사 진행)으로 돌아감

### 2-2. 학생 — 논문 심사 > 학위논문제출 (기존 화면)

| 항목 | 동작 |
|---|---|
| 목록 | 기존 컬럼 그대로. 지난 차수 제출 행도 함께 표시 (기본단계 → 차수 순) |
| 관리 컬럼 | [보기](상세) 또는 [제출](제출 화면) 하나 |
| 제출구분 | 기존 'N차 제출' |
| 심사결과 | 기존: 결과 전 '-', 확정 후 합격 / 조건부합격 / 불합격 |
| 구 이력 조회 | 지난 제출 행 [보기] → 기존 상세 → [총평 보기] (신청 기간과 무관) |
| 보완 제출 | 조건부합격 후 다음 차수 행 [제출] → 기존 '기존 제출 내역' 블록과 함께 제출 |
| **제출취소** | [보기] 상세 화면의 [제출취소] — 결과 확정 전이고 제출기간일 때만 표시. 심사 진행 중이면 "심사가 진행 중이어서 제출을 취소할 수 없습니다.", 아니면 확인 후 파일 삭제 → 미제출 (신청 유지). 제출취소 기간 정책 회신 전까지 제출기간 적용 |

### 2-3. 교수 — 논문 심사 > 학위논문심사 (기존 화면)

| 항목 | 동작 |
|---|---|
| 목록 | 기존 컬럼에 **'차수'** 추가. 같은 학생의 1차·2차 심사가 별도 행 |
| 위원장 판정 | 기존 화면 그대로 (합격 / 조건부합격 / 불합격) |
| 조건부합격 | 기존 '재심 정보'(재심 심사위원·평가표) 입력 → 확정 시 다음 차수 심사가 목록에 생성 (위원장 + 지정 위원). 학생 제출 전에는 논문파일 다운로드 없음 |
| 불합격 | 기존 흐름. 다음 차수는 학생이 다시 신청하고 배정된 뒤 생성 |

### 2-4. 관리자

- 논문신청·심사위원등록·심사일정현황·학위논문심사·대시보드 모두 **기존 화면 그대로** (신청구분·차수·별도 상태 표시 없음)
- 관리자는 **조회만** 함 — 철회·제출취소 기능 없음 (논문신청 상세의 '철회기간'은 기존 날짜 표시, 일정 관리의 '신청철회'는 학생 철회 기간 설정)
- 요구서 반영 결과만 보임: 불합격 시 이전 신청은 리셋되어 현재 신청만 표시, 철회된 건은 목록에 없음

## 3. 시연 방법

학생 화면 상단 '목업 시연' 바에서 시나리오를 고르고, [초기화]로 처음 상태로 돌립니다.

| 시나리오 | 상황 | 확인 포인트 | 바로가기 |
|---|---|---|---|
| ① 재심사 진행 | 예비심사 1차 불합격 | 논문신청 '재심사 진행' + [관리] / 학위논문제출 1차 제출 [보기]→[총평 보기] | `?screen=thesis-application&scenario=retry-open` |
| ② 심사 미진행 | 다시 신청 + 2차 제출, 평가 0명 | 신청 상세 [논문 신청 철회] 가능, 제출 상세 [제출취소] 가능 | `?screen=thesis-application&scenario=not-started&detail=prelim` / `?screen=thesis-submission&scenario=not-started&view=prelim` |
| ③ 심사 진행 중 | 다시 신청 + 2차 제출, 평가 1명 | 철회·제출취소 누르면 불가 팝업 | `?screen=thesis-application&scenario=in-progress&detail=prelim` |
| ④ 조건부합격 후 보완 제출 | 본심사 1차 조건부합격 | 신청 없이 2차 제출, 기존 제출 내역 | `?screen=thesis-submission&scenario=conditional&form=final` |

## 4. 목업의 한계

1. 화면 간 데이터 연동 없음 — 교수가 판정해도 학생 화면은 바뀌지 않으며, 학생 화면은 시연 바로 상태를 재현
2. 기본단계당 세부단계가 1개라, 요구서의 '채점 완료 세부단계 보존' 상황(한 단계에 세부단계 여러 개)은 표현되지 않음
3. 제출취소 기간, DB View(JXLB-7)는 화면에 표현하지 않음 — 질의 회신 후 정의
4. 지도교수 변경 반영(JXLB-1 예외)은 표현하지 않음
