# 심사 신청 ~ 재심사 프로세스 (목업 기준)

- 작성일: 2026-10-06 / 새로 작성: 2026-10-07 (재정비 목업 기준) / **갱신: 2026-10-08 (심사 건 1행·신청 철회와 제출취소 연동·재심사 상태 구분 없음)**
- 기준: 요구사항정의서 JXLB-1·2·7, `재심사_목업_재정비_계획_20261007.md`
- 목업: https://hycu-new.vercel.app (학생 `/student-v3/student-dashboard`, 교수 `/professor-v3/professor-dashboard-proposal`, 관리자 `/admin-v3`)
- 원칙
  - 명시된 요구사항만 구현, 기존 화면·버튼·상태값·용어 재사용. 재심사도 일반 심사와 같이 취급 (별도 상태·구분 없음)
  - 같은 심사 건(학생 · 기본단계)의 1·2차는 목록 1행, 이전 차수는 상세(관리) 화면에 기존 화면 그대로 표시 — 학생·교수·관리자 공통
  - 목록의 관리 컬럼은 상세(페이지) 이동 1개만. 철회·제출취소는 학생이 상세 화면에서, 해당 기간일 때만
  - 신청 철회 = 제출취소 (어느 쪽에서 해도 신청과 제출이 함께 철회)
  - 관리자 화면은 조회만

## 1. 전체 흐름

```
[학생] 논문신청 [관리] → 신청완료
   → [학생] 학위논문제출: N차 제출 (목록은 기본단계마다 1행)
   → [관리자] 심사위원 배정 · 일정 등록 (기존)
   → [교수] 심사위원 평가 → 위원장 판정
        ├ 합격 ─────── 단계 완료
        ├ 조건부합격 ── 같은 심사 건 안에서 '재심 정보' 저장 → [학생] 신청 없이 같은 행에서 N+1차 제출 → 다시 심사
        └ 불합격 ───── [학생] 신청상태 '미신청'(신청 리셋) → [관리]로 다시 신청(동일·이후 학기) → 같은 행이 N+1차 제출
```

- 이전 기본단계 결과는 영향 없음, 재심사 횟수 제한 없음 (요구서)
- 이전 차수의 제출 파일·평가·위원장 총평은 보존하고, 같은 심사 건의 상세 화면에서 조회 (요구서)

---

## 2. 화면별 동작

### 2-1. 학생 — 논문 심사 > 논문신청 (기존 화면)

| 신청상태 | 조건 | 관리 버튼 |
|---|---|---|
| 미신청 (기존) | 신청 이력 없음, 불합격 확정(신청 리셋), 철회한 경우 | [관리] → 기존 신청 모달 |
| 신청완료 (기존) | 신청함 | [관리] → 신청 상세 (기존 모달) — [논문 신청 철회]는 철회기간에만 |

**신청 철회 (요구서, 신청 상세 화면에서)**
- 심사 진행 중(심사위원 1명 이상 평가)이거나 결과가 확정됐으면 "심사가 진행중이므로 철회할 수 없습니다."
- 그 외에는 "해당 단계에서 제출한 자료와 내역은 모두 초기화됩니다(합격여부가 결정된 단계 제외) 그래도 철회하시겠습니까?" 확인 후 철회 → "논문 신청 내역이 초기화되었습니다."
- 철회하면 신청과 해당 신청의 제출 자료가 함께 삭제 → 미신청. 학위논문제출의 해당 행도 이전 차수 상태로 돌아감

### 2-2. 학생 — 논문 심사 > 학위논문제출 (기존 화면)

| 항목 | 동작 |
|---|---|
| 목록 | 기존 그대로 기본단계마다 최신 차수 1행 |
| 관리 컬럼 | [보기](상세) 또는 [제출](제출 화면) 하나 |
| 제출구분 | 기존 'N차 제출' |
| 심사결과 | 기존: 결과 전 '-', 확정 후 합격 / 조건부합격 / 불합격 |
| 이전 차수 조회 | [보기]·[제출] 화면 위쪽에 차수마다 기존 '기존 제출 내역' 블록 ('기존 제출 내역 (N차 제출)') — 결과·[총평 보기]. 신청 기간과 무관 |
| 보완 제출 | 조건부합격 후 같은 행 [제출] (신청 없이) |
| **제출취소** | [보기] 상세의 [수정] 옆 [제출취소] — 결과 확정 전이고 제출기간일 때만 표시. 신청 철회와 같은 처리(조건·문구 동일), 신청도 함께 철회되어 논문신청 '미신청' |

### 2-3. 교수 — 논문 심사 > 학위논문심사 (기존 화면)

| 항목 | 동작 |
|---|---|
| 목록 | 기존 컬럼·버튼([심사], 위원장은 [승인]) 그대로, 심사 건마다 최신 차수 1행 (차수 컬럼 없음) |
| 이전 심사 내역 조회 | 목록 해당 행 [심사]/[승인] → 심사 상세 위쪽 'N차 심사' 영역 (기존 화면 그대로, 읽기 전용) → 아래 현재 차수 영역에서 평가·판정 |
| 조회 범위 | 위원장: 이전 차수 위원별 평가 현황·위원장 결정·총평 전체 / 위원: 이전 차수 본인 평가표 (참여하지 않았으면 표시 없음) |
| 위원장 판정 | 기존 화면 그대로 (합격 / 조건부합격 / 불합격) |
| 조건부합격 | 기존 '재심 정보'(재심 심사위원·평가표) 입력 → 같은 심사 건에 저장 (목록에 새 행 없음) |
| 불합격 | 기존 흐름. 다음 차수는 학생이 다시 신청하고 배정된 뒤 같은 심사 건으로 표시 |

### 2-4. 관리자

- 논문신청·심사위원등록·심사일정현황·대시보드: **기존 화면 그대로** (신청구분·차수·별도 상태 표시 없음)
- 학위논문심사: 심사 건마다 1행, [상세보기]에서 이전 차수 심사 내역을 교수 위원장 화면과 같이 조회
- 관리자는 **조회만** 함 — 철회·제출취소 기능 없음 (논문신청 상세의 '철회기간'은 기존 날짜 표시, 일정 관리의 '신청철회'는 학생 철회 기간 설정)
- 요구서 반영 결과만 보임: 불합격 시 이전 신청은 리셋되어 현재 신청만 표시, 철회된 건은 목록에 없음

## 4. 목업의 한계

1. 화면 간 데이터 연동 없음 — 교수가 판정해도 학생 화면은 바뀌지 않으며, 학생 화면은 시연 바로 상태를 재현
2. 기본단계당 세부단계가 1개라, 요구서의 '채점 완료 세부단계 보존' 상황(한 단계에 세부단계 여러 개)은 표현되지 않음
3. 제출취소 기간, DB View(JXLB-7)는 화면에 표현하지 않음 — 질의 회신 후 정의
4. 지도교수 변경 반영(JXLB-1 예외)은 표현하지 않음
