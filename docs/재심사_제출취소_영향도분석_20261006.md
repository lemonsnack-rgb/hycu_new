> 목업이므로 실데이터 구조 개편(3장)은 하지 않음. **화면별 시나리오 Mock**으로 정책이 보이고, 버튼 동작은 해당 페이지 안에서만 상태가 바뀜(화면 간 연동 없음).

### 0-1. 확정 정책

| 구분 | 확정 내용 |
|---|---|
| 판정 선택지 | 합격 / **조건부합격** / 불합격 (3개 유지) |
| 조건부합격 | **당해 학기 재심**. 심사 신청 불필요 → 학생이 자료만 재제출 → 위원장이 지정한 재심 위원이 심사. 재심 결과로 **조건부합격 반복 가능** |
| 불합격 | **다음 학기 재심사**. 해당 기본단계 **심사신청부터** 다시 진행. 기존 제출·심사 내역은 보존 |
| 차수 표기 | 차수는 **불합격 시에만** 증가 (1차 → 2차). 조건부 재심은 차수 안에서 **재심1, 재심2…** (예: `본심사 1차 재심1`, `본심사 2차`) |
| 제출취소 | 제출한 결과물을 삭제(신청 철회와 별개). 조건: **심사 미진행**(평가한 위원 0명)일 때만. **기간 조건은 없음**(제출취소 기간 정책이 미정이라 이번엔 제외) |
| 신청 철회 | 요구사항 규칙 적용: 심사 진행 중(1명 이상 평가)이거나 완료 → 철회 불가 팝업 / 미진행 → 초기화 안내 팝업 후 철회 |
| 학생 이력 | 자료제출 목록은 **심사단계명 + 심사결과**만 표시, **심사단계명 클릭 시 차수별 기록**(제출물·결과·위원장 총평) 표시. 기간과 무관하게 조회 가능 |
| 교수 목록 | 이전 차수 건도 **목록에 유지**, 차수·결과 표시. 2차는 새 행으로 표시 |
| 제외 | 관리자 '제출취소 기간' 설정 화면, 대시보드, 공지문구 |

### 0-3-1. 학생 시연용 시나리오 선택 바 (목업 전용)

학생 화면은 로그인 학생 1명 기준이므로, 심사신청·자료제출 화면 상단에 **목업 전용 시나리오 선택 바**를 두고 고르면 두 화면의 Mock 상태가 함께 바뀌게 함.

| 시나리오 | 논문작성계획서 | 예비심사 | 본심사 | 확인 포인트 |
|---|---|---|---|---|
| ① 재신청 가능 | 1차 합격 | 1차 **불합격**, 신청기간 열림 | 미신청(선행단계 미완료) | [2차 신청], 이력 팝업 |

| ③ 심사 미진행 | 1차 합격 | 2차 신청완료 + 제출완료, 평가 0명 | 미신청 | [철회] 가능, [제출취소] 가능 |

### 0-4. 완성 조건 (사용자 관점)
- 학생이 **불합격 단계에서 다음 학기에 2차 신청**할 수 있고, 이전 1차 기록을 단계명 클릭으로 언제든 볼 수 있음
- 학생이 **심사가 시작되지 않은 제출물만** 제출취소할 수 있음
- 학생이 **심사가 진행 중이면 신청을 철회할 수 없고**, 미진행이면 안내 후 철회됨
- 교수가 **불합격 판정 시 재신청 안내**를 보고 확정하며, 목록에서 1차/2차가 구분되어 보임
- 교수가 **조건부합격 판정을 실제로 제출**할 수 있고, 학생은 신청 없이 재심 제출
- 관리자 목록에서 차수와 철회/재심사 대상 상태가 보임
- 세 화면 모두 콘솔 오류 없이 동작

## 2. 핵심 결론

1. **세 화면 모두 재심사·제출취소 기능이 없음.** 철회는 학생 화면에서 조건 없이 데이터를 지우는 수준.
2. **"차수(시도)" 개념이 데이터에 없음.** 신청·배정·평가·결과·일정이 모두 `배정ID` 1건 기준이라, 2차 심사를 만들면 1차 이력을 덮어씀. → **데이터 구조 변경이 선결 과제 (영향도 상)**
3. **신청 ↔ 제출 ↔ 배정 ↔ 심사 데이터가 서로 연결돼 있지 않음.** 학생 신청 데이터, 학생 제출 데이터, 관리자 배정 데이터, 교수 심사 데이터가 각각 독립된 Mock이며 ID·학생·단계명이 서로 다름. 철회/제출취소 시 "연쇄 처리"를 보여줄 기반이 없음.
4. **'기간' 설정이 실제로 쓰이지 않음.** 관리자 일정 설정값은 저장만 되고 어디서도 읽지 않으며, 학생 화면은 기간과 무관하게 버튼이 동작함. 제출취소 기간 정책을 구현하려면 이 연결부터 필요.
5. **정책과 정면 충돌하는 기존 로직 존재**: 조건부합격 = 재심, 재심 횟수 상한('재심 횟수 초과'), "1회에 한해 무료 재심사" 공지 문구 등.

> 목업 특성상 앱 간 실시간 연동(학생이 취소 → 교수 목록에서 사라짐)은 불가능함(페이지별 메모리 데이터). 각 화면에 **동일 시나리오를 표현하는 Mock 데이터**를 맞춰 넣는 방식으로 시연하는 것을 전제로 함.
