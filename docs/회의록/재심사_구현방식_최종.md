# 재심사 구현 방식 최종 결정

## 결론: 재심은 **같은 단계 내에서 재심 차수로 관리**

---

## 1. 이전 방식의 문제점

### 방식: 학생별 customStages에 재심 단계 추가

**문제 1**: 워크플로우 무결성 깨짐
```
워크플로우 템플릿: [1, 2, 3, 4, 5]
학생 A: [1, 2, 3, 4, 4.5(재심), 5]  ← 템플릿과 다름!
학생 B: [1, 2, 2.5(재심), 3, 4, 5]  ← 템플릿과 다름!
```
- 관리자가 만든 워크플로우가 학생별로 변형됨
- 감사 추적 불가능
- 이력 관리 복잡

**문제 2**: 재심 위치 예측 불가
```
예비심사 2차(order: 3) → 조건부합격
  → 재심 단계를 어디 넣지?
  → 3과 4 사이? (3.5)
  → 그럼 4번(본심사)이 4.5로 밀림
  → 최종논문은 5.5?
```

**문제 3**: 단계 순서 재조정의 복잡성
- 재심 추가 시마다 모든 이후 단계의 order를 +1 해야 함
- 버그 발생 가능성 높음

---

## 2. 최종 해결 방법

### **재심은 같은 단계 내에서 "심사 차수"로 관리**

**핵심 원칙**:
- 워크플로우 템플릿은 절대 변경하지 않음
- 학생의 `currentStageOrder`는 템플릿의 order와 항상 동일
- 재심은 별도 테이블로 관리

### 3.3 심사 이력 테이블 (신규)

```javascript
ExaminationHistory {
  id: 'EXAM_001',
  studentId: 'STU001',
  stageOrder: 4,               // 어느 단계의 심사인지
  stageName: '본심사',
  examRound: 1,                // 심사 차수 (1: 최초, 2: 1차 재심, 3: 2차 재심)
  examType: 'initial',         // 'initial' | 'reexam'

  // 심사 정보
  committeeChair: 'PROF001',
  committeeMembers: ['PROF001', 'PROF002', 'PROF003'],
  submissionDate: '2026-01-15',
  evaluationDate: '2026-01-20',

  // 결과
  result: '조건부합격',        // '합격' | '조건부합격' | '불합격'

  // 재심 정보 (조건부합격인 경우만)
  reexamInfo: {
    method: '대면',            // '대면' | '서면'
    evaluationType: 'full',    // 'full' (전체 심사위원) | 'chair_only' (위원장만)
    deadline: '2026-02-15',    // 재심 논문 제출 기한
    requirements: '연구방법론 부분 보완 필요',
    status: 'pending'          // 'pending' | 'submitted' | 'completed'
  }
}
```

**재심 방식 조합**:

### 초기 구현 (2가지 조합)
| method | evaluationType | 설명 |
|--------|---------------|------|
| 대면 | full | 전체 심사위원이 모여서 대면 심사 |
| 서면 | chair_only | 심사위원장만 서면으로 확인 (일반적) |

**초기 구현 로직**:
- UI에서 `method`만 선택받음
- `method === '대면'` → `evaluationType = 'full'` 자동 설정
- `method === '서면'` → `evaluationType = 'chair_only'` 자동 설정

### 향후 확장 가능 (4가지 조합)
데이터 구조는 이미 4가지 조합을 지원하므로, 향후 필요 시 UI만 수정하면 확장 가능:

| method | evaluationType | 설명 |
|--------|---------------|------|
| 대면 | full | 전체 심사위원이 모여서 대면 심사 |
| 대면 | chair_only | 심사위원장만 대면으로 확인 |
| 서면 | full | 전체 심사위원이 각자 서면 평가 |
| 서면 | chair_only | 심사위원장만 서면으로 확인 |

**확장 방법**: 자동 설정 로직 제거 후 UI에서 `evaluationType` 선택 필드 추가

```javascript
function processEvaluationResult(studentId, stageOrder, result, reexamInfo) {
  // UI에서 전달받은 reexamInfo = {
  //   method: '대면' | '서면',
  //   deadline: '2026-02-15',
  //   requirements: '연구방법론 보완 필요'
  // }

  // 1. evaluationType 자동 설정 (초기 구현)
  const evaluationType = reexamInfo.method === '대면' ? 'full' : 'chair_only';

  // 2. 심사 이력 저장
  const examRound = getNextExamRound(studentId, stageOrder);
  const examHistory = {
    id: generateId(),
    studentId: studentId,
    stageOrder: stageOrder,
    examRound: examRound,
    examType: examRound === 1 ? 'initial' : 'reexam',
    result: result,
    evaluationDate: new Date().toISOString(),
    reexamInfo: result === '조건부합격' ? {
      method: reexamInfo.method,
      evaluationType: evaluationType,  // 자동 설정됨
      deadline: reexamInfo.deadline,
      requirements: reexamInfo.requirements,
      status: 'pending'
    } : null
  };

  saveExaminationHistory(examHistory);

  // 3. 결과에 따른 처리
  if (result === '합격') {
    // 다음 단계로 이동
    const student = getStudent(studentId);
    const nextStageOrder = stageOrder + 1;
    changeStage(studentId, nextStageOrder);

  } else if (result === '조건부합격') {
    // 학생은 현재 단계 유지 (재심 대기)
    // currentStageOrder 변경 없음!

    // 학생에게 알림 발송
    const methodText = reexamInfo.method === '대면' ? '대면' : '서면';
    const evalText = evaluationType === 'full'
      ? '전체 심사위원'
      : '심사위원장';

    sendNotification(studentId, {
      type: 'reexam_required',
      message: `재심이 필요합니다. ${reexamInfo.deadline}까지 수정논문을 제출하세요.`,
      details: {
        method: `${methodText} 재심 (${evalText} 평가)`,
        deadline: reexamInfo.deadline,
        requirements: reexamInfo.requirements
      }
    });

  } else if (result === '불합격') {
    // 현재 단계 유지, 다음 학기 재신청
    const student = getStudent(studentId);
    student.canProceed = false;
  }
}
```

### 6.2 재심 차수 계산

```javascript
function getNextExamRound(studentId, stageOrder) {
  // 해당 학생의 해당 단계에서 심사 이력 조회
  const histories = ExaminationHistory.filter(h =>
    h.studentId === studentId && h.stageOrder === stageOrder
  );

  // 다음 차수 반환 (이력이 없으면 1, 있으면 max + 1)
  if (histories.length === 0) {
    return 1;
  } else {
    const maxRound = Math.max(...histories.map(h => h.examRound));
    return maxRound + 1;
  }
}
```

```javascript
function getStudentExamStatus(studentId) {
  const student = getStudent(studentId);
  const currentStage = getCurrentStage(student);

  // 현재 단계의 최신 심사 이력 조회
  const latestExam = ExaminationHistory
    .filter(h => h.studentId === studentId && h.stageOrder === student.currentStageOrder)
    .sort((a, b) => b.examRound - a.examRound)[0];

  if (!latestExam) {
    return {
      status: 'not_started',
      message: '심사 미시작'
    };
  }

  if (latestExam.result === '조건부합격') {
    const reexamInfo = latestExam.reexamInfo;
    const methodText = reexamInfo.method === '대면' ? '대면' : '서면';
    const evalText = reexamInfo.evaluationType === 'full'
      ? '전체 심사위원'
      : '심사위원장';

    if (reexamInfo.status === 'pending') {
      return {
        status: 'reexam_pending',
        message: '재심 논문 제출 대기',
        reexamType: `${methodText} 재심 (${evalText})`,
        deadline: reexamInfo.deadline,
        requirements: reexamInfo.requirements
      };
    } else if (reexamInfo.status === 'submitted') {
      return {
        status: 'reexam_submitted',
        message: '재심 평가 대기',
        reexamType: `${methodText} 재심 (${evalText})`
      };
    }
  }

  if (latestExam.result === '합격') {
    return {
      status: 'passed',
      message: '심사 통과'
    };
  }

  if (latestExam.result === '불합격') {
    return {
      status: 'failed',
      message: '심사 불합격'
    };
  }
}
```

### 6.4 재심 평가 진행 (평가자 확인)

```javascript
function canEvaluateReexam(professorId, examHistory) {
  // 재심이 아니면 모두 평가 가능
  if (examHistory.examType !== 'reexam') {
    return true;
  }

  const reexamInfo = examHistory.reexamInfo;

  // 전체 심사위원 평가: 모든 위원이 평가 가능
  if (reexamInfo.evaluationType === 'full') {
    return examHistory.committeeMembers.includes(professorId);
  }

  // 심사위원장만 평가: 위원장만 가능
  if (reexamInfo.evaluationType === 'chair_only') {
    return examHistory.committeeChair === professorId;
  }

  return false;
}

// 교수 화면에서 재심 평가 버튼 표시 여부
function showReexamEvaluationButton(professorId, studentId) {
  const latestExam = getLatestExam(studentId);

  if (!latestExam || latestExam.examType !== 'reexam') {
    return false;
  }

  if (latestExam.reexamInfo.status !== 'submitted') {
    return false;  // 학생이 아직 제출 안 함
  }

  return canEvaluateReexam(professorId, latestExam);
}
```

## 8. 장점

### 8.1 워크플로우 무결성 유지
- 템플릿은 절대 변경되지 않음
- 모든 학생이 동일한 워크플로우 사용
- 감사 추적 가능

### 8.2 단순하고 명확한 구조
- 재심 = 같은 단계의 다음 차수
- 복잡한 order 재조정 불필요
- 버그 가능성 낮음

### 8.3 확장 가능
- N차 재심도 같은 방식으로 처리
- 심사 이력 완전 추적
- 통계 및 분석 용이

### 8.4 기존 코드 영향 최소
- StudentThesisStage 구조 변경 없음
- 단계 이동 로직 변경 없음
- ExaminationHistory만 추가

## 9. 불합격 후 다음 학기 재신청 프로세스

### 9.1 재심 vs 재신청 비교

| 구분 | 재심 (Reexam) | 재신청 (Reapplication) |
|------|--------------|----------------------|
| 발생 조건 | 조건부합격 | 불합격 |
| 시기 | 같은 학기 내 | 다음 학기 |
| 단계 이동 | currentStageOrder 유지 | currentStageOrder 유지 |
| 심사위원 | 동일 (또는 위원장만) | 새로 구성 가능 |
| 심사 차수 | examRound 증가 | examRound 1로 초기화 |
| 논문 신청 | 재제출만 | 전체 신청 절차 다시 |

### 9.2 불합격 처리 프로세스

```javascript
function handleFailureForNextSemester(studentId, stageOrder) {
  const student = getStudent(studentId);

  // 1. 심사 이력에 최종 불합격 기록
  const examHistory = {
    id: generateId(),
    studentId: studentId,
    stageOrder: stageOrder,
    examRound: getNextExamRound(studentId, stageOrder),
    examType: 'initial',
    result: '불합격',
    evaluationDate: new Date().toISOString(),
    semester: getCurrentSemester(),
    reexamInfo: null
  };

  saveExaminationHistory(examHistory);

  // 2. 현재 논문 신청 종료 처리
  const currentApplication = getCurrentThesisApplication(studentId, stageOrder);
  if (currentApplication) {
    currentApplication.status = 'failed';  // 신청 실패 처리
    currentApplication.closedAt = new Date().toISOString();
    updateThesisApplication(currentApplication);
  }

  // 3. 학생 상태 업데이트
  student.canProceed = false;  // 다음 단계 진행 불가
  student.needsReapplication = true;  // 재신청 필요 플래그
  student.reapplicationStage = stageOrder;  // 재신청 필요 단계

  // 4. currentStageOrder는 그대로 유지!
  // student.currentStageOrder는 변경하지 않음
  // 같은 단계에서 다음 학기에 재신청 필요

  // 5. 학생에게 알림
  sendNotification(studentId, {
    type: 'need_reapplication',
    message: '심사 불합격으로 다음 학기에 재신청이 필요합니다.',
    details: {
      failedStage: getStageName(stageOrder),
      nextAvailableSemester: getNextSemester()
    }
  });
}
```

### 9.3 다음 학기 재신청 프로세스 (전체 프로세스 재실행)

재신청 시 **논문 신청부터 평가까지 전체 프로세스**를 처음부터 다시 실행:

1. **논문 신청** (학생)
2. **심사위원 구성** (관리자 또는 지도교수)
3. **논문 제출** (학생)
4. **심사 평가** (심사위원)
5. **결과 확인** (합격/조건부합격/불합격)

```javascript
function processReapplication(studentId, stageOrder, applicationData) {
  const student = getStudent(studentId);

  // 1. 재신청 가능 여부 확인
  if (!student.needsReapplication || student.reapplicationStage !== stageOrder) {
    throw new Error('재신청 대상이 아닙니다.');
  }

  // 2. 학기 확인 (다음 학기만 재신청 가능)
  const currentSemester = getCurrentSemester();
  const failedSemester = getFailedSemester(studentId, stageOrder);
  if (!isNextSemester(failedSemester, currentSemester)) {
    throw new Error('재신청은 다음 학기에만 가능합니다.');
  }

  // 3. 재신청 상태 초기화
  student.canProceed = true;  // 진행 가능 상태로 복구
  student.needsReapplication = false;
  student.reapplicationStage = null;
  updateStudent(student);

  // 4. 새로운 논문 신청 생성 (전체 프로세스 처음부터)
  const newApplication = {
    id: generateId(),
    studentId: studentId,
    stageOrder: stageOrder,
    applicationDate: new Date().toISOString(),
    semester: currentSemester,
    isReapplication: true,  // 재신청 표시
    previousApplications: getPreviousApplications(studentId, stageOrder),  // 이전 신청 이력

    // 새로 입력받아야 할 정보들
    title: applicationData.title,  // 논문 제목 (새로 입력)
    abstract: applicationData.abstract,  // 초록 (새로 입력)
    keywords: applicationData.keywords,  // 키워드 (새로 입력)

    // 심사위원 구성 (관리자가 새로 지정)
    committeeChair: null,  // 미지정 상태
    committeeMembers: [],  // 미지정 상태
    committeeAssignedAt: null,

    // 논문 제출 (학생이 새로 업로드)
    thesisPdfUrl: null,  // 미제출
    attachments: [],  // 미제출
    submittedAt: null,

    // 심사 일정 (심사위원장이 새로 설정)
    examDate: null,
    examLocation: null,

    // 신청 상태
    status: 'application_submitted'  // 신청 접수 단계
  };

  saveThesisApplication(newApplication);

  // 5. 알림 발송
  sendNotification(studentId, {
    type: 'reapplication_submitted',
    message: `${getStageName(stageOrder)} 재신청이 접수되었습니다.`,
    details: {
      stage: getStageName(stageOrder),
      semester: currentSemester,
      applicationId: newApplication.id,
      nextStep: '심사위원 구성 대기 중'
    }
  });

  // 6. 관리자에게 알림 (심사위원 구성 필요)
  sendNotificationToAdmin({
    type: 'committee_assignment_required',
    message: `${student.name} 학생의 ${getStageName(stageOrder)} 재신청 건 - 심사위원 구성이 필요합니다.`,
    studentId: studentId,
    applicationId: newApplication.id
  });

  return newApplication;
}
```

### 9.4 재신청 후 전체 프로세스 흐름

```

  ↓
학생: needsReapplication = true
학생: currentStageOrder = 4 (본심사 유지)
  ↓
[다음 학기]
  ↓
① 학생이 "재신청하기" 버튼 클릭
  → 논문 제목, 초록, 키워드 새로 입력
  → ThesisApplication 생성 (status: 'application_submitted')
  ↓
② 관리자/지도교수가 심사위원 구성
  → committeeChair, committeeMembers 지정
  → status: 'committee_assigned'
  ↓
③ 학생이 논문 및 서류 제출
  → thesisPdfUrl, attachments 업로드
  → status: 'thesis_submitted'
  ↓
④ 심사위원장이 심사 일정 설정
  → examDate, examLocation 설정
  → status: 'exam_scheduled'
  ↓
⑤ 심사위원들이 평가 진행
  → 각 위원이 평가 입력
  → status: 'under_evaluation'
  ↓
⑥ 심사위원장이 최종 결과 입력
  → ExaminationHistory 생성 (examRound: 1로 초기화!)
  → result: '합격' | '조건부합격' | '불합격'
  → status: 'completed'
  ↓
[합격] → currentStageOrder = 5 (다음 단계)
[조건부합격] → 재심 프로세스
[불합격] → 다시 재신청 필요
```

## 9.8 재신청 vs 재심 상세 비교

| 항목 | 재심 (Reexam) | 재신청 (Reapplication) |
|------|--------------|----------------------|
| **발생 조건** | 조건부합격 | 불합격 |
| **시기** | 같은 학기 내 | 다음 학기 |
| **신청서 작성** | ✗ 불필요 | ✅ 필요 (제목, 초록 등 재입력) |
| **심사위원 구성** | 동일 (또는 위원장만) | ✅ 새로 구성 |
| **논문 제출** | ✅ 수정논문만 제출 | ✅ 전체 논문 새로 제출 |
| **심사 일정** | 재심 일정만 설정 | ✅ 전체 일정 새로 설정 |
| **ThesisApplication** | 기존 것 유지 | ✅ 새로 생성 |
| **ExaminationHistory** | examRound 증가 (2, 3...) | ✅ examRound 1로 초기화 |
| **currentStageOrder** | 유지 | 유지 (합격 후 이동) |
| **프로세스** | 재심만 진행 | ✅ 전체 프로세스 재실행 |

## 9.9 학교 메일 기준 재신청 케이스

### 석사 본심사
1. **불합격** → 최종 불합격 → **다음학기 본심 재신청** (전체 프로세스 재실행)
2. **조건부합격 → 재심(대면) 불합격** → 최종 불합격 → **다음학기 본심 재신청** (전체 프로세스 재실행)

### 박사 본심사
1. **본심 1차 불합격** → 본심 2차 불가, 본심 1차로 종결 → **(다음학기 본심사 신청)** (전체 프로세스 재실행)
2. **본심 2차 불합격** → **다음학기 본심사 재진행** (전체 프로세스 재실행)

**재신청 프로세스 (전체 재실행)**:
1. ✅ 논문 신청서 작성 (제목, 초록, 키워드 재입력)
2. ✅ 심사위원 구성 (관리자/지도교수가 새로 지정)
3. ✅ 논문 제출 (학생이 새로 업로드)
4. ✅ 심사 일정 설정 (심사위원장이 새로 설정)
5. ✅ 심사 평가 (심사위원들이 평가)
6. ✅ 결과 확인 (합격/조건부합격/불합격)

**중요**:
- 재신청 시 학생은 **같은 단계에 머물러** 있음 (currentStageOrder 변경 없음)
- **ThesisApplication 새로 생성** (이전 것과 별개)
- **ExaminationHistory의 examRound는 1로 초기화** (새로운 신청이므로)
- 논문 신청부터 평가까지 **전체 절차를 처음부터** 다시 진행

## 10. 예상 질문과 답변

**Q: 학생 화면에서 "본심사(재심)"로 보이게 할 수는 없나요?**
A: 가능합니다. UI에서만 재심 차수를 확인해서 "(재심 진행 중)" 표시를 추가하면 됩니다.

**Q: 재심 단계를 별도로 표시하려면?**
A: ExaminationHistory를 조회해서 재심 차수가 2 이상이면 재심 배지를 표시합니다.

**Q: 박사 본심 1차 조건부합격은?**
A: 본심 1차와 2차는 **다른 단계**(order: 6, 7)입니다. 1차에서 조건부합격이면 그냥 2차로 진행됩니다. (재심 아님)

**Q: N차 재심은 어떻게?**
A: examRound를 계속 증가시키면 됩니다. (1차, 2차, 3차 재심...)

**Q: 재신청과 재심의 차이는?**
A:
- **재심**: 조건부합격 후 같은 학기 내에 수정 후 재평가 (examRound 증가)
- **재신청**: 불합격 후 다음 학기에 해당 단계를 처음부터 다시 신청 (examRound 1로 초기화)

**Q: 재신청 시 심사위원은 동일해야 하나요?**
A: 아니요. 재신청은 새로운 신청이므로 심사위원을 새로 구성할 수 있습니다.

**Q: 재신청 시 이전 심사 이력은 어떻게 되나요?**
A: ExaminationHistory에 모두 보관되며, 재신청 시 참고용으로 조회 가능합니다.

### 10.1 불합격 처리 방식의 중요한 결정

#### 10.1.1 불합격 시에도 다음 단계 이동 가능

**핵심 결정**:
- 불합격 판정 후에도 교수 승인으로 다음 단계로 이동 가능
- 이는 기존 재심사 설계와 **다른 추가 요구사항**

**회의록 원문**:
> "불합격할 때도 넘어가도록 해야 된다"
> "불합격해도 뒤로는 넘겨야 되잖아요"
> "이번에는 불합격이고 근데 어쨌든 다음 2차에서 다시 해"

**의미**:
- 조건부합격 → 재심 (같은 단계 유지) ← 기존 설계
- **불합격 → 다음 단계 이동 (교수 승인 시)** ← 신규 요구사항
- 불합격이어도 코멘트를 남기고 단계를 종료하여 다음 단계로 진행 가능

**구현 영향**:
```javascript
function processEvaluationResult(studentId, stageOrder, result, approveNext) {
  if (result === '합격') {
    changeStage(studentId, stageOrder + 1);  // 다음 단계 이동
  }
  else if (result === '조건부합격') {
    // 현재 단계 유지, 재심 정보 저장 (기존 설계)
    saveReexamInfo(...);
  }
  else if (result === '불합격') {
    // 신규 요구사항: 불합격이어도 교수가 승인하면 다음 단계 이동
    if (approveNext) {
      changeStage(studentId, stageOrder + 1);  // 다음 단계 이동
      saveComment('불합격이지만 다음 단계 진행 승인');
    } else {
      // 기존 설계: 재신청 필요
      student.needsReapplication = true;
    }
  }
}
```

### 10.2 평가 유형 구분

#### 10.2.1 최종 심사 vs 중간 단계

**A. 최종 심사 (본부 관리 단계)**
- 심사위원 + 심사위원장이 **반드시** 평가 필요
- 3인 심사위원 체계로 평가표 활용
- **회의록 원문**: "최종이라고 찍히는 거는 구성한 심사위원과 심사위원장이 꼭 반드시 평가를 해야 해요"

**B. 중간 단계 (학과 자율 관리)**
- 평가표 없이 **지도교수가 직접 승인**
- 심사 평가표를 매핑할 필요 없이 화면 내에서 합격/불합격 선택
- **회의록 원문**: "최종이 아닌 n차 단계들은 그렇게 해도 되고 아니면 지도 교수가 넘겨도 된다"

**구현 영향**:
```javascript
ThesisStage {
  stages: [
    {
      order: 1,
      name: '연구계획서',
      evaluationType: 'advisor_approval',  // ← 지도교수 승인
      requiresCommittee: false
    },
    {
      order: 2,
      name: '본심사 1차',
      evaluationType: 'advisor_approval',  // ← 지도교수 승인
      requiresCommittee: false
    },
    {
      order: 3,
      name: '본심사 3차',
      evaluationType: 'committee_evaluation',  // ← 심사위원 평가
      requiresCommittee: true,
      allowReexam: true
    }
  ]
}
```

**핵심 결정**:

### 10.6 학기별 관리 방식

**핵심 결정**:
- 학기 개념 필요성 확인
- **회의록 원문**: "만약 이걸 관리하려면 학기가 필요하고"

**학기 전환 시 처리**:
- 학생이 졸업하지 못하고 다음 학기로 넘어갈 경우, 새로운 학기로 매핑
- **회의록 원문**: "하이가 26년도 1학기에 들어왔을 때... 얘는 졸업을 못 했어 그러면 얘를 새로 20년도 2학기에 이 레고 블록을 그냥 새로 매핑하면서"

**조회 기준**:
- 학생은 **현재 학기 기준**으로 조회됨
- 과거 이력은 남아있지만, 관리는 현재 학기 기준

```javascript
function transitionToNextSemester(studentId, nextSemester) {
  const student = getStudent(studentId);

  if (!student.hasGraduated) {
    // 졸업하지 못한 경우, 다음 학기로 매핑
    student.semester = nextSemester;
    student.isExtended = true;
```

### 10.7 재심사 설계와의 충돌 분석

#### 10.7.1 기존 재심사 설계

```
합격 → 다음 단계 이동
조건부합격 → 재심 (같은 단계 유지)
불합격 → 재신청 필요 (다음 학기)
```

#### 10.7.2 회의록 추가 요구사항

```
합격 → 다음 단계 이동
조건부합격 → 재심 (같은 단계 유지)
불합격 → 교수 승인 시 다음 단계 이동 가능  ← 신규
```

#### 10.7.3 통합 설계안

```javascript
function processEvaluationResult(studentId, stageOrder, result, options) {
  // 1. 합격 처리
  if (result === '합격') {
    changeStage(studentId, stageOrder + 1);
  }

  // 2. 조건부합격 처리 (재심)
  else if (result === '조건부합격') {
    saveExaminationHistory({
      examRound: getNextExamRound(studentId, stageOrder),
      result: '조건부합격',
      reexamInfo: {
        method: options.reexamMethod,
        evaluationType: options.evaluationType,
        deadline: options.deadline,
        requirements: options.requirements,
        status: 'pending'
      }
    });
    // currentStageOrder 유지 (재심 대기)
  }

  // 3. 불합격 처리 (신규 분기 추가)
  else if (result === '불합격') {
    saveExaminationHistory({
      examRound: getNextExamRound(studentId, stageOrder),
      result: '불합격'
    });

    // 신규: 교수 승인으로 다음 단계 이동 옵션
    if (options.approveNext === true) {
      // 불합격이지만 다음 단계로 이동
      changeStage(studentId, stageOrder + 1);
      saveComment('불합격이지만 교수 승인으로 다음 단계 진행');

      // 알림 발송
      sendNotification(studentId, {
        type: 'failed_but_proceed',
        message: '불합격 판정이지만 다음 단계로 진행합니다. 이전 단계 보완 사항을 반영하여 진행해주세요.'
      });
    } else {
      // 기존: 재신청 필요
      student.needsReapplication = true;
      student.canProceed = false;

      sendNotification(studentId, {
        type: 'need_reapplication',
        message: '불합격으로 다음 학기 재신청이 필요합니다.'
      });
    }
  }
}
```
