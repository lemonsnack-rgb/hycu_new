# 사용자 관리 기능 구현 방안

**작성 일시:** 2026.01.27
**기능명:** 관리자 > 시스템 설정 > 사용자 관리

---

## 1. 개요

관리자가 전체 사용자(학생, 교수, 관리자)를 조회하고, 특정 사용자로 로그인할 수 있는 기능을 개발함.

### 3.3 관리 컬럼 버튼 구성
- **로그인 버튼**: 파란색 테두리, "해당 사용자로 로그인" 기능
- **수정 버튼**: 회색 버튼 (향후 확장용, 현재는 비활성화 또는 미구현)
- **탈퇴 버튼**: 빨간색 텍스트 버튼 (향후 확장용, 현재는 비활성화 또는 미구현)

이미지를 보면 "로그인" 버튼이 파란색 테두리로 강조되어 있음.

## 4. 검색 기능

### 4.1 검색 조건
| 검색 항목 | 타입 | 옵션 | 필수 여부 |
|----------|------|------|----------|
| 관리자 구분 | 드롭다운 | 전체, 학생, 교수, 관리자 | 선택 |

### 4.2 검색 버튼

- 검색 초기화: "초기화" 버튼 (회색 배경, 옵션)

## 5. 데이터 조회 및 표시

### 5.1 데이터 소스
**질문 2:** 현재 사용자 데이터는 어디에 저장되어 있나요?
- admin_data.js의 mockUsers 배열 사용?
- 별도 API 엔드포인트 호출?
- 기존 데이터 구조 예시를 확인해야 함

### 5.2 필터링 로직
```javascript
// 예시 구조
function filterUsers(users, filters) {
    return users.filter(user => {
        // 관리자 구분 필터
        if (filters.adminType !== '전체' && user.userType !== filters.adminType) {
            return false;
        }

        // 사용자 구분(학과) 필터
        if (filters.department !== '전체' && user.department !== filters.department) {
            return false;
        }

        // 학적상태 필터
        if (filters.academicStatus !== '전체' && user.academicStatus !== filters.academicStatus) {
            return false;
        }

        // 학번/사번 검색
        if (filters.idNumber && !user.idNumber.includes(filters.idNumber)) {
            return false;
        }

        return true;
    });
}
```

### 5.3 페이징 처리
- 페이지당 표시 개수: 10, 20, 50, 100 (드롭다운 선택)
- 기본값: 10개
- 페이징 네비게이션: 이전/다음, 페이지 번호

## 6. 로그인 기능

### 6.1 로그인 버튼 동작
사용자 행의 "로그인" 버튼 클릭 시:

1. **확인 대화상자 표시**
   ```
   [사용자명](학번/사번)으로 로그인하시겠습니까?
   로그인 후 해당 사용자의 화면으로 이동됩니다.

   [취소] [확인]
   ```

2. **로그인 처리**
   - 현재 관리자 세션 정보 임시 저장 (원래 관리자로 돌아올 수 있도록)
   - 선택한 사용자 정보로 세션 변경
   - 사용자 유형별 화면으로 리다이렉트:
     - 학생 → /student/
     - 교수 → /professor/
     - 관리자 → /admin/

**질문 3:** 관리자가 다른 사용자로 로그인한 후, 다시 관리자 계정으로 돌아오는 기능이 필요한가요? 필요하다면 어떤 방식으로 구현할까요?
- 방안 A: 헤더에 "관리자 모드로 돌아가기" 버튼 추가
- 방안 B: 세션 타임아웃 시 자동으로 관리자 계정으로 복귀
- 방안 C: 로그아웃 시 관리자 계정으로 복귀

### 6.2 보안 고려사항
**질문 4:** 로그인 시 보안 로그를 남겨야 하나요?
- 관리자가 누구의 계정으로 언제 로그인했는지 기록
- 감사 추적(Audit Trail) 기능 필요 여부
