# 프로토타입 화면별 논의사항 - 목적 중심
**회의 성격:** 현재 구현된 프로토타입을 화면별로 리뷰하며 진행

**후속 메일:** 2026.01.24 한양사이버대학교 대학원교학팀 김호정
- 심사원칙과 교수자/행정 처리 편의성 사이 논의 정리
- 시스템은 일반적인 심사절차에 따라 구현하고 행정부서에 운영 가이드 제공 방향


# 회의 및 메일 핵심 요약

## 핵심 결정사항
**1. 심사 주체 명확화 (메일)**
- 해당 단계의 심사자(지도교수, 심사위원회)가 직접 평가 수행
- 평가 없이 단계 승급, 행정직원이 평가 결과 입력하는 구조 지양
- 시스템은 일반적인 심사절차에 따라 구현하고 행정부서에 운영 가이드 제공

**2. 학기 개념 도입 (회의)**
- 목적: 대상자 관리를 위해 필요
- 지도교수 배정은 연속성 유지, 단계별로는 학기 구분

**3. 심사 vs 승인 분리 (회의 + 메일)**
- 최종 단계: 심사표 기반 정식 평가 (심사위원회)
- 중간 단계: 지도교수가 직접 승인 (합격/불합격 + 코멘트)
- 행정 부담 감소

**4. 조건부합격 프로세스 추가 (메일)**
- 석사: 본심 1회, 조건부합격자만 재심
- 박사: 본심 2회, 1차 조건부합격자는 2차에서 재심
- 재심 방식: 대면(심사위원 전체) / 서면(심사위원장 또는 지도교수 위임)

**5. 부속서류 제출 기능 (메일)**
- N차 심사, 재심 시 수정전후대비표 등 부속서류 제출
- 학생: 논문 + 부속서류 제출
- 교수/관리자: 논문 + 부속서류 다운로드/확인

**6. 평가표 다양화 (메일)**
- 서술형 평가: 심사자 의견 입력, 종합평정 책임자 구분
- 척도형 평가: 현재 사용 중인 양식 기반

**7. 심사위원 배정 편의성 (메일)**
- 프로포절과 예비심사 각각 구성 가능
- 예비심사 N차, 본심사 N차는 기존 구성 내역 재사용 가능

**8. 플로우 시각화 (회의)**
- 목적: 학생과 교수 모두 진행 상태를 한눈에 파악

**9. 메뉴 구조 개선 (회의)**
- 학생: 제출 위치를 쉽게 찾을 수 있도록 단계 유형 구분
- 교수: 전체 제출물 조회와 심사 대상을 구분하여 확인

**10. 불합격 vs 조건부합격 (회의 + 메일)**
- 원칙(메일): 불합격은 해당 단계에서 종결, 조건부합격을 활용
- 운영(회의): 중간 단계에서는 교수 판단으로 코멘트 남기고 다음 단계 이동 가능
- 정책적 과제: 교수들의 반발 예상, 교학팀의 안내 및 설득 필요

## 1. 교수 화면

### 1.1 논문 지도 학생 목록

#### 논의된 문제점
- 현재 프로토타입에서는 학생이 현재 어느 단계에 있는지 텍스트로만 표시됨
- 전체 과정 중 어디까지 왔는지 직관적으로 파악하기 어려움

#### 회의록 원문
> "교수님한테는 자기 논문 지도 학생이 5명 있으면 그 5명이 어떤 단계에 있는지가 보여져야 된다"

#### 기능 추가 목적
교수가 자신의 지도 학생들의 논문 진행 현황을 한눈에 파악할 수 있도록:
- 목록 화면에서 현재 단계를 텍스트로 표시
- 학생 정보 클릭 시 팝업으로 전체 플로우 시각화 제공
- 색상을 통해 진행 상태를 시각적으로 표현

---

### 1.2 논문 지도 활동

#### 논의된 문제점
- 학생의 진행 단계가 업데이트되면서 과거 피드백의 단계 정보가 사라질 수 있다는 우려
- 예: 연구 계획서 단계에서 준 피드백이 본심사 단계로 단계가 바뀌면서 함께 바뀔 가능성
- 학생이 먼저 파일을 업로드해야만 교수가 피드백을 줄 수 있는 구조

#### 회의록 원문
> "나는 연구 계획서 단계에서는 분명히 교수님이 제 연구 계획서 피드백을 줬을 거고 예비 심사 단계에서 예비 심사 피드백을 줬을 텐데 그거를 다 단계가 그럼 마지막에는 본심사로 싹 다 바뀐다는 거잖아. 그거 아닌 거 같은데 그건 아닌 것 같아"
> "논문 지도 활동에서는 요 뷰어 영역에서 여기 학생들 학생이 먼저 참석할 수 있도록 만드는 기능적인 고려"

#### 기능 추가 목적
단계별 지도 활동의 히스토리를 명확하게 유지하고 양방향 소통을 지원하기 위해:
- 피드백 작성 시 해당 단계를 함께 저장하여 히스토리 보존
- 교수가 먼저 피드백을 작성할 수 있는 옵션 제공 (학생의 파일 업로드를 기다리지 않아도 됨)
- 양방향 소통이 가능한 구조로 개선

### 1.3 학위 논문 심사 (제출 내역 조회 + 심사 평가)

#### 논의된 문제점
- 현재 프로토타입: "학위 논문 심사" 메뉴에 심사표가 있는 최종 단계만 표시됨
- 교수가 학생의 중간 제출물(프로포즈, 예비심사 1차 등)을 확인할 수 있는 메뉴가 없음
- 행정직원이 평가 결과를 대신 입력하는 구조는 지양해야 함

#### 회의록 원문 (회의)
> "교수님 입장에서는 학위 논문 심사야. 근데 심사라고 했을 때 나 본 심사 이제 1차 하는데 학생들이 뭘 냈는지 보고 싶어요. 그럼 나 같으면은 교수님 입장에서는 그때는 논문 심사로 들어올 때 그러니까 1 2차를 보고 싶어"
> "본심사 1차예요. 근데 심사표원은 심사는 안 한다고 했어. 근데 교수님 입장에서의 시스템적인 거 말고요. 그냥 교수님 입장에서의 이 본심사 1차는 논문 심사잖아. 근데 심사에 왔는데 없어. 그리고 조회만 떠 있는 거예요."
> "교수님 화면에서는 학생이 제출한 모든 목록이 보이는 메뉴와 그중에서 심사로 꽂혀 있는 애를 보는 걸 그냥 나누면 되겠다"

#### 메일 원문 (정리)
> **1. 심사주체**
> 1) 해당 단계의 심사자(단계에 따라 지도교수, 심사위원회)가 직접 평가 수행
> 예. 논문작성계획서 – 지도교수
> 석사 예비심사 - 지도교수 또는 예비심사위원회
> 박사 예비심사 – 예비심사위원회
> 2) 평가 없이 단계 승급, 행정직원이 평가 결과 입력하는 구조 지양

#### 기능 추가 목적
교수가 학생의 모든 제출물을 확인하고, 심사표 필요 여부에 따라 적절한 평가를 수행하도록:

**A. 메뉴 구조 분리**
1. **제출 내역 조회 메뉴**: 학생이 제출한 모든 산출물 확인 가능
2. **심사 평가 메뉴**: 평가가 필요한 단계만 표시

**B. 심사 주체에 따른 처리 방식**
**1) 지도교수 단독 심사 (중간 단계)**
- 논문작성계획서, 석사 예비심사 등
- 지도교수가 산출물 확인 후 직접 승인 처리
- 합격/불합격 선택 + 코멘트 작성
- 승인 시 다음 단계로 자동 이동

**회의록 원문:**
> "심사표 없을 때... 여기서 산출물 보고 여기서 승인 처리해서 승인되면은 상태 값이 승인으로 바뀌고"
> "승인 버튼을 두고 옆에다가 얘는 합격 불합격 하나 이제 선택할 수 있는 값을 두고 불합격이시면 일단 승인"

**2) 심사위원회 평가 (최종 단계)**
- 박사 예비심사, 석사/박사 본심사 최종
- 심사위원 + 심사위원장이 반드시 평가표 작성
- 정식 심사 프로세스 진행

**회의록 원문:**
> "최종이라고 찍히는 거는 구성한 심사위원과 심사위원장이 꼭 반드시 평가를 해야 해요"

**C. 불합격 처리의 유연성**
불합격 판정 후에도 교수의 판단에 따라 다음 단계로 진행 가능하도록:
- 불합격이어도 교수가 "승인 및 다음 단계 이동" 선택 가능
- 모든 평가 결과와 교수의 승인 여부는 코멘트와 함께 기록으로 남김

**회의록 원문:**
> "불합격해도 뒤로는 넘겨야 되잖아요"
> "그거는 코멘트를 남겨놓고 일단 단계 그건 레이블을 좀 고민해 봐야겠지만 거기다가 기록을 남기게끔"

**메일 원문:**
> **3. 심사결과 평가 미반영 옵션 요청 철회, 조건부합격 처리 프로세스 추가 요청**
> 불합격은 해당 단계에서 종결, 다음단계 미진행
> 수정 보완해서 다음 단계 진입이 가능한 경우 조건부합격을 활용하라는 가이드를 행정에서 안내

### 1.4 조건부합격 및 재심사 처리

#### 논의된 문제점
- 현재 프로토타입: 조건부합격 개념이 없음
- 재심사 방식 지정, 재심사 일정, 재심사자 정보 등을 관리할 수 있는 기능 부재

#### 메일 원문
> **3. 조건부합격 처리에 대한 프로세스 추가 요청**
> 수정 보완해서 다음 단계 진입이 가능한 경우 조건부합격을 활용하라는 가이드를 행정에서 안내
> 이를 운영하려면 아래 내용을 반영할 수 있도록 조건부합격 처리(예. 재심사 방식 지정, 재심사 일정, 재심사자 정보 등) 필요
>
> **■ 석사 : 본심 1회, 조건부합격자만 재심**
> ① 합격 -> 최종합격
> ② 조건부합격
> -> 재심(대면): 대면일정을 잡아 심사위원(장) 심의(수정전후표 등 부속서류 포함 수정논문 제출) -> 합격 (최종합격)
> -> 불합격(최종 불합격) -> 다음학기 본심 재신청
> -> 재심(서면): 심사위원(장)이 승인, 지도교수에게 위임하여 승인할 수 있음
> ③ 불합격 -> 최종 불합격
>
> **■ 박사 본심 2회 : 1차 논문제출자 모두 심사, 2차 1차 합격 + 1차 조건부합격자 심사**
> 1) 본심 1차
> ① 합격 -> 본심 2차 진행
> ② 조건부 합격 -> 다음차수 재심사 (본심 2차 진행 (2차에서 보완 재심사))
> ③ 불합격 -> 본심 2차 불가, 본심 1차로 종결(다음학기 본심사 신청)
>
> 2) 본심 2차(최종)
> ① 합격 -> 최종합격
> ② 조건부 합격 -> 재심(서면) : 심사위원장이 재심사 논문제출 기간을 설정하고 제출기간에 재심사 해서 최종합격 또는 불합격 / 심사위원(장)이 승인, 지도교수에게 위임하여 승인할 수 있음
> ③ 불합격 -> 다음학기 본심사 재진행

#### 기능 추가 목적
조건부합격 판정 후 재심사 프로세스를 체계적으로 관리하기 위해:

**A. 조건부합격 처리 화면**
- 평가 결과 입력 시 합격/조건부합격/불합격 중 선택
- 조건부합격 선택 시 재심사 정보 입력 모달 표시

**B. 재심사 방식 설정**
- **재심(대면)**: 대면 일정 지정, 심사위원(장) 심의, 수정전후표 등 부속서류 제출
- **재심(서면)**: 논문 제출 기간 설정, 심사위원(장) 승인 또는 지도교수 위임 승인

**C. 재심사자 지정**
- 석사: 심사위원장 또는 지도교수에게 위임
- 박사: 심사위원회 전체 또는 위원장

**D. 지도교수 위임 기능**
- 서면 재심 시 "지도교수에게 위임" 옵션 제공
- 위임 시 지도교수가 최종 승인 권한 가짐

### 1.5 평가표 작성

#### 논의된 문제점
- 현재 프로토타입: 기본적인 평가표만 존재
- 서술형 평가와 척도형 평가 구분 필요

#### 메일 원문
> **4. 평가표 추가**
> - 서술형 평가 추가
>   심사자 서술형 의견 입력 / (심사자가 지도교수 단독인 경우 지도교수가 종합평정, 심사위원 구성단계인 경우 위원장이 종합평정)
> - 척도형 평가 추가 (붙임의 평가표 양식참조 / 현재 사용중인 양식)

#### 기능 추가 목적
다양한 평가 방식을 지원하고 종합평정 책임을 명확히 하기 위해:

**A. 서술형 평가**
- 심사자가 자유롭게 의견 입력
- 종합평정 책임자:
  - 지도교수 단독 심사: 지도교수가 종합평정

## 2. 학생 화면

### 2.1 대시보드 - 플로우 시각화

#### 논의된 문제점
- 현재 프로토타입: 전체 논문 지도 과정을 한눈에 볼 수 있는 시각적 요소 부족
- 학생이 현재 어느 위치에 있고 무엇을 해야 하는지 직관적으로 파악하기 어려움

#### 회의록 원문
> "학생처럼 그 플로우가 있는 거를 교수한테도... 학생별로 보여주자는 건데"

#### 기능 추가 목적
학생이 자신의 현재 위치와 남은 단계를 명확하게 파악할 수 있도록:
- 대시보드에 플로우 이미지를 표시하여 현재 진행 단계를 시각적으로 표현
- 제출 기간, 평가 여부 등 관련 정보도 함께 표시
- 학생이 다음에 무엇을 해야 하는지 직관적으로 파악 가능

### 2.2 학위 논문 제출 (논문 + 부속서류)

#### 논의된 문제점
- 현재 프로토타입: "학위 논문 제출" 메뉴 아래 모든 단계의 제출이 포함되어 있음
- 학생이 "중간보고서"를 제출하려고 할 때 "학위 논문 제출" 메뉴에서 찾기 어려움
- N차 심사, 재심 시 수정전후대비표 등 부속서류 제출 기능 없음

#### 회의록 원문
> "학생 입장에서는 논문 심사하는 메뉴를 여기다 넣을 텐데 여기에는 논문뿐만 아니라 각 단계별로 n차에 해당하는 모든 산출물 여기다 다 넣게 되면... 학생 입장에서는 처음 눌렀을 때 어디다 넣지에 대해서 헷갈려 할 것 같아서"
> "중간을 제출하려고 이 목적성을 가지고 이 시스템에 들어왔을 때 하는 곳을 찾을 수 있을까요? 학위 논문 제출이라는 메뉴잖아요."
> "논문 작성 계획서 예비 심사 본 심사라는 거를 앞에 큰 꼭지들을 단계 유형이었나 그거를 넣고 세부 심사 단계가 지도 단계 유형이 거기에 들어가고"

#### 메일 원문
> **5. 각 단계별 N차, 재심의 경우 수정전후대비표(붙임자료) 등 부속서류 제출이 있음. 이 부분도 시스템으로 받을 수 있도록 구현 필요**
> - (학생화면) 논문 + 부속서류 제출
> - (교수/관리자화면) 심사에서 하나의 버튼 "논문다운로드"만 있음, 논문+부속서류 다운로드/확인 기능

#### 기능 추가 목적
학생이 현재 제출해야 할 산출물의 위치를 직관적으로 찾고, 필요한 부속서류를 함께 제출할 수 있도록:

**A. 메뉴 구조 개선**
- 단계 유형(지도 단계 유형)을 구분하여 표시
  - 예: 논문 작성 계획서, 예비 심사, 본 심사
- 세부 심사 단계를 하위에 표시
  - 예: 예비 심사 1차, 2차, 3차

**B. 부속서류 제출 기능**
- 논문 파일 + 부속서류(수정전후대비표 등) 동시 업로드
- N차 심사, 재심 시 부속서류 필수 제출
- 제출 완료 시 논문과 부속서류가 하나의 제출 건으로 관리됨

### 2.3 재심사 논문 제출

#### 메일 원문

- 수정논문 + 수정전후대비표 등 부속서류 제출
- 제출 완료 시 심사자에게 알림 발송

## 3. 관리자 화면

### 3.1 지도 교수 배정 및 학기 관리
#### 논의된 문제점
- 현재 프로토타입: 지도 단계만 실시간으로 관리
- 학기별로 대상자를 조회할 수 있는 구조 없음
- 학생이 졸업하지 못하고 다음 학기로 넘어갈 경우 처리 방법 불명확

#### 회의록 원문
> "연도 학기가 지금 학생이 신청하고 제출하고 심사 받네. 그 연도 학기는 명확하거든요. 근데 대상자로서 해당 연도 학기에 해당 연도 학기의 상태를 또 관리를 해줘야 해서"
> "지도 단계를 지금 실시간으로만 관리를 하고 있고요."
> "지도 교수 배정에 대한 지도 교수와 학생 값을 어떻게 계속 가져가는지 졸업하기 전에 그리고 학생이 변경 신청해서 변경 처리가 되기 전까지는 그냥 쭉쭉 연장인 거예요."
> "26년도 1학기에 하다가 얘는 졸업하지 못하고 26년도 2학기에 왔을 때 하니는 2년 6년도 2학기로 또 다시 매핑을 다시 매핑까지는 아니지만 어쨌든 연감기가 바뀌면서"

#### 기능 추가 목적
학기별 학생 상태 관리 및 대상자 조회를 위해:

**A. 지도 교수 배정의 연속성**
- 지도 교수 배정은 졸업 전까지 자동 연장
- 학생이 졸업하거나 지도교수 변경 신청을 하기 전까지는 계속 유지
- 교수 변경 시 기존 히스토리는 그대로 보존

**B. 단계별 학기 관리**
- 각 단계(프로포즈, 예비심사 등)에서는 학기별 대상자 조회 필요
- 한 학기 안에 여러 단계 진행 가능
- 졸업하지 못한 학생은 다음 학기로 자동 연장

**C. 대상자 조회 조건**
- 학기별 대상자는 특정 조건으로 필터링
- 예: "3학기 차 이상 논문 작성 계획서 통과한 학생"

### 3.3 지도 단계 등록 및 워크플로우 관리

#### 논의된 문제점
- 모든 단계에 심사위원을 배정하고 관리하는 것은 행정 부담이 큼
- 중간 단계는 지도교수가 직접 관리할 수 있어야 함
- 본부가 관리해야 하는 "최종" 단계와 구분 필요

#### 회의록 원문
> "학위 논문 제출 이 부분에 대해서는 여기선 본부에서 관리하는 최종이라는 아이들만 여기서 관리해도 되는 건지"
> "최종이라는 단계 있잖아요. 걔를 제외한 나머지는 사실상 지도교사 다 한다라는 거잖아요. 네 캐릭터를 맺어줄 게 사실 없는 거거든요."
> "정리를 하면 네 최종이라고 찍히는 거는 구성한 심사위원과 심사위원장이 꼭 반드시 평가를 해야 해요. 그리고 본 심사 앞단에 있는 최종이 아닌 n차 단계들은 그렇게 해도 되고 아니면 지도 교수가 넘겨도 된다"
> "그러면 안 그러면은 심사위원 배정을 그때그때 다 해줘야 되는데 그것도 행정에서 하는 거는 부담일 것 같아."

#### 기능 추가 목적
본부가 관리해야 하는 "최종" 단계와 지도교수가 관리하는 중간 단계를 명확히 구분:

**A. 최종 단계 (본부 관리)**
- 심사위원 + 심사위원장이 반드시 평가표 작성
- 정식 심사 프로세스 진행
- 본부에서 심사위원 배정 및 관리

**B. 중간 단계 (지도교수 관리)**
- 지도교수가 직접 승인/불합격 처리
- 심사위원 배정 불필요
- 행정 부담 최소화

### 3.4 심사위원 배정 및 재사용

#### 논의된 문제점
- 예비, 본심사 N차마다 심사위원을 새로 구성해야 하는지 불명확
- 예비심사 내 프로포절과 예비심사의 심사위원이 다를 수 있음
- N차 진행 시 매번 새로 선택하는 것은 불편함

#### 메일 원문
> **2. 심사위원 구성 문의**
> 1) 현 시스템 기준 예비, 본심사 N차 마다 심사위원을 구성해주는 구조인지 문의
> 2) 문의배경
>   - 예비심사(유형단계) 내에서 프로포절과 예비심사를 만들도록 되어있으며, 프로포절 심사위원과 예비심사위원는 다름. 이에 따라 각각 구성가능한지 검토
>   - 예비심사 N차는 본심사 N차의 경우, 처음 구성한 위원이 동일하게 진행. 따라서 각 N차에 대한 구성이라면 매번 선택이 아니라 기존 구성 내역을 불러와 적용할 수 있는 기능도 제공하여 편의성 개선 가능 여부 등 검토

#### 기능 추가 목적
심사위원 배정의 편의성을 높이기 위해:

**A. 단계별 심사위원 구성**
- 프로포절 심사위원과 예비심사 심사위원을 각각 구성 가능
- 각 단계의 특성에 맞는 심사위원 배정

**B. 기존 구성 내역 재사용**
- 예비심사 N차, 본심사 N차의 경우 처음 구성한 위원이 동일하게 진행
- 매번 새로 선택하지 않고 기존 구성 내역을 불러와 적용
- 필요 시 일부 위원 변경 가능

**C. 행정 부담 감소**
- 최종 단계에만 심사위원 배정
- 중간 단계는 지도교수가 직접 처리

## 4. 공통 이슈 및 정책 결정

### 4.1 심사 원칙과 편의성 사이의 균형

#### 논의된 문제점
- 교수 업무 증가에 대한 우려 (캔버스 사례)
- 행정직원이 대신 처리하는 것은 심사 원칙에 어긋남
- 시스템은 원칙대로 구현하되 운영은 가이드로 보완

#### 정책적 과제
- **시스템**: 지도교수가 각 단계를 직접 평가/승인하는 것이 올바른 심사 원칙
- **운영**: 교수들의 저항이 예상되므로 행정부서에서 운영 가이드 제공
- **교학팀 역할**: 교수들에게 시스템 사용에 대한 충분한 안내와 설득 필요

---

### 4.2 심사 vs 승인 개념 정리

#### 논의된 문제점
- 학생, 교수, 관리자 각각의 용어가 혼재되어 혼란 발생
- "심사"와 "승인"의 차이가 명확하지 않음

#### 회의록 원문
> "학생 입장에서는 논문 심사라고 안 하고 투고라고 불러요. 그냥 논문 투고를 여기서 제출이라고 부른다고 치면은 학생이 모든 투고하는 산출물은 여기 여기 메뉴에 다 쌓여 있고 이 중에서 심사표가 달려 있는 땅땅땅의 대상이 되는 애들만 교수님의 심사 메뉴에 있으면 되는 거잖아요."

#### 기능 추가 목적
학생, 교수, 관리자 각각의 용어를 명확히 구분하여 혼란 방지:

**용어 정리:**
1. **제출 (학생)**: 모든 산출물 제출
2. **심사 (교수 - 최종 단계)**: 심사표 기반 정식 평가 (심사위원회)
3. **승인 (교수 - 중간 단계)**: 합격/불합격 + 코멘트로 단계 진행 (지도교수)

---

### 4.3 불합격 vs 조건부합격 처리

#### 논의된 문제점
- 회의: 불합격이어도 다음 단계로 진행 가능해야 함
- 메일: 불합격은 해당 단계에서 종결, 조건부합격을 활용하라는 가이드 제공

#### 회의록 원문
> "불합격해도 뒤로는 넘겨야 되잖아요"
> "그거는 코멘트를 남겨놓고 일단 단계 그건 레이블을 좀 고민해 봐야겠지만 거기다가 기록을 남기게끔"

#### 메일 원문
> **3. 심사결과 평가 미반영 옵션 요청 철회, 조건부합격 처리 프로세스 추가 요청**
> **불합격은 해당 단계에서 종결, 다음단계 미진행**
> 수정 보완해서 다음 단계 진입이 가능한 경우 조건부합격을 활용하라는 가이드를 행정에서 안내

#### 기능 추가 목적
불합격과 조건부합격의 차이를 명확히 하여 학생의 학업 진행을 적절히 관리:

**A. 조건부합격 (권장)**
- 수정 보완 후 다음 단계 진입 가능
- 재심사 프로세스 진행
- 학생에게 보완 기회 제공

**B. 불합격**
- 해당 단계에서 종결
- 다음 학기 재신청 필요
- 단, 중간 단계에서는 교수 판단으로 코멘트 남기고 다음 단계 이동 가능 (운영 가이드로 처리)

### 4.4 D-Collection 제출 관리

#### 논의된 문제점
- 본심사 합격 후 D-Collection 제출이 필요
- 시스템에서 해당 단계를 관리할지 결정 필요

#### 회의록 원문
> "디컬렉션을 제출 안 하면 그다음에 다시 제출해야 돼요."

> "그거를 제출하는 거를 이 논문 지도 시스템에서 관리를 해야 되는지 여부를 여쭤본 거예요."

#### 기능 추가 목적
본심사 합격 후 D-Collection 제출을 관리할지 결정 필요:
- 시스템에서 해당 단계를 추가할지
- 외부 링크로 연결하여 안내만 할지
