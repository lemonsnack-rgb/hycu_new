## 1. 변경 사항 요약

### 1.1 핵심 변경사항

| 구분 | 기존 | 변경 후 | 영향도 |
|------|------|---------|--------|
| **평가 유형** | 일괄 심사위원 평가 | 중간 단계(지도교수 승인) + 최종 단계(심사위원 평가) 이원화 | 🔴 High |
| **불합격 처리** | 불합격 → 재신청 필요 | 불합격 → 교수 승인 시 다음 단계 이동 가능 | 🔴 High |
| **교수 메뉴** | 단일 메뉴 | 제출 내역(조회) + 심사 대상(평가) 분리 | 🟡 Medium |
| **승인 프로세스** | 평가표 기반 | 합격/불합격 선택 + 승인 버튼 | 🟡 Medium |
| **학기 관리** | 실시간 단계만 관리 | 학기별 학생 상태 관리 | 🟡 Medium |

### 1.2 신규 개념

1. **evaluationType**: `advisor_approval` (지도교수 승인) vs `committee_evaluation` (심사위원 평가)
2. **allowFailAndProceed**: 불합격 시 다음 단계 이동 허용 플래그
3. **제출 내역 vs 심사 대상**: 교수 화면 메뉴 분리
4. **학기별 관리**: 학생의 현재 활동 학기 추적

## 2. 교수 화면 변경사항

### 2.1 메뉴 구조 변경 (🔴 High)

#### 기존 구조
```
교수 메뉴
└── 학생 제출물 관리
    └── 모든 제출물 조회 및 평가
```

#### 변경 후 구조
```
교수 메뉴
├── 제출 내역 (전체 조회)
│   ├── 학생 A - 연구계획서
│   │   └── [조회] (평가표 없음)
│   ├── 학생 B - 본심사 1차 논문
│   │   └── [조회] [승인] (평가표 없음, 지도교수 승인)
│   └── 학생 C - 본심사 3차 논문
│       └── [조회] [심사 평가] (평가표 있음)
│
└── 심사 대상 (평가 필요)
    ├── 학생 C - 본심사 3차 (평가표 있음)
    │   └── [심사 평가 하기]
    └── 학생 D - 최종 논문 (평가표 있음)
        └── [심사 평가 하기]
```

**회의록 근거**:
> "학생이 제출한 모든 목록이 보이는 메뉴와 그중에서 심사로 꽂혀 있는 애를 보는 걸 그냥 나누면 되겠다"

**구현 영향**:
- 교수 메뉴 2개 신규 추가
- 제출 내역: 전체 조회 + 단계별 필터링
- 심사 대상: 평가표 있는 건만 표시

```
│                                         │
│ ─────────────────────────────────       │
│                                         │
│ 📝 평가 및 승인                         │
│                                         │
│ [평가 선택] *                           │

│ ⚪ 불합격                                │

│ [코멘트]                                │

│ │ 연구방법론 부분 보완 필요   │        │
│ │ 다음 단계에서 반영 바랍니다 │        │
│ └─────────────────────────────┘        │
│                                         │
```

**회의록 근거**:
> "승인 버튼을 두고 옆에다가 얘는 합격 불합격 하나 이제 선택할 수 있는 값을 두고 불합격이시면 일단 승인"
> "불합격해도 뒤로는 넘겨야 되잖아요"

**주요 기능**:
1. 합격/불합격 선택 (라디오 버튼)
2. 코멘트 입력 (Textarea)
3. 승인 버튼 클릭 시:
   - 합격 선택 → 다음 단계 이동 + "합격" 기록
   - 불합격 선택 → 다음 단계 이동 + "불합격" 기록 + 코멘트 필수

**구현 필요 사항**:
- [ ] 승인 프로세스 API 신규 개발
- [ ] 불합격+승인 시 알림 로직
- [ ] 코멘트 저장 테이블

## 3. 학생 화면 변경사항

### 3.1 불합격 상태 표시 (🟡 Medium)

#### 기존 vs 변경

**기존**:
```
불합격 → 재신청 필요 → 다음 학기까지 대기
```

**변경 후**:
```
불합격 → 교수 승인 시 다음 단계 진행 가능
       → 교수 거부 시 재신청 필요
```

#### 화면 구성

**케이스 1: 불합격 + 교수 승인 (다음 단계 이동)**
```
┌─────────────────────────────────────────┐
│ 논문 진행 단계                          │
├─────────────────────────────────────────┤
│                                         │
│ ●───●───●───●───○                      │
│ 계획서 예비1 예비2 본심 최종            │
│ 완료  완료  완료  진행 대기             │
│  ✓    ✓    ✓    ⏳                      │
│                                         │
│ 현재 단계: 본심사 1차                   │
│                                         │
│ ⚠️ 이전 단계 평가 결과                   │
│ • 연구계획서: 불합격                    │
│ • 교수 코멘트: "연구방법론 부분 보완    │
│   필요. 본심사에서 반영 바랍니다."      │
│ • 다음 단계 승인: 2026-01-25            │
│                                         │
│ 📌 안내                                  │
│ 이전 단계에서 불합격 판정을 받았으나,    │
│ 지도교수님 승인으로 다음 단계로         │
│ 진행합니다. 보완 사항을 반영하여        │
│ 진행해주세요.                           │
└─────────────────────────────────────────┘
```

**케이스 2: 불합격 + 교수 거부 (재신청 필요)**

```
│ 완료  완료  완료  불합격 대기           │
│  ✓    ✓    ✓    ✗                      │
│                                         │
│ 현재 단계: 본심사 3차 (최종)            │
│                                         │
│ ⚠️ 재신청 안내                           │
│ • 본심사 불합격으로 다음 학기에         │
│   재신청이 필요합니다.                  │
│ • 재신청 가능 학기: 2026-1학기          │
│                                         │
│ [다음 학기 재신청하기] (비활성)         │

```

**구현 필요 사항**:
- [ ] 불합격 상태 구분 로직 (교수 승인 여부)

## 5. 데이터 구조 변경사항

### 5.1 ThesisStage (워크플로우 템플릿) 확장

```javascript
// 기존
ThesisStage {
  stages: [
    {
      order: 1,
      name: '연구계획서',
      evaluationRequired: true
    }
  ]
}

// 변경 후
ThesisStage {
  stages: [
    {
      order: 1,
      name: '연구계획서',
      evaluationType: 'advisor_approval',      // ← 신규: 평가 유형
      requiresCommittee: false,                // ← 신규: 심사위원 필요 여부
      allowReexam: false,                      // ← 신규: 재심 허용
      allowFailAndProceed: true                // ← 신규: 불합격 시 다음 단계 이동 허용
    },
    {
      order: 2,
      name: '본심사 1차',
      evaluationType: 'advisor_approval',
      requiresCommittee: false,
      allowReexam: false,
      allowFailAndProceed: true
    },
    {
      order: 3,
      name: '본심사 3차 (최종)',
      evaluationType: 'committee_evaluation',  // ← 심사위원 평가
      requiresCommittee: true,
      allowReexam: true,                       // ← 재심 허용
      allowFailAndProceed: false               // ← 불합격 시 재신청 필요
    }
  ]
}
```

**신규 필드 설명**:
- `evaluationType`: `advisor_approval` (지도교수 승인) | `committee_evaluation` (심사위원 평가)
- `requiresCommittee`: 심사위원 구성 필요 여부
- `allowReexam`: 재심 허용 여부 (조건부합격 시)
- `allowFailAndProceed`: 불합격 시 교수 승인으로 다음 단계 이동 허용
