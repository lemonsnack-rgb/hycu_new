### 1.1 단계지도유형관리

| 항목 | 논의 내용 | 구현 방안 | 수용 여부 |
|------|----------|----------|----------|
| **지도단계유형관리 삭제** | 본부공통관리하는 3개 항목(논문작성계획서, 예비심사, 본심사) 이외 관리할 이슈가 없으므로 유형관리 화면 삭제 제안 | 지도단계유형관리 화면 삭제, 심사유형만 존재 | ⚠️ **부분 수용** - 확인 필요 |

### 1.3 지도단계등록

| 항목 | 논의 내용 | 구현 방안 | 수용 여부 |
|------|----------|----------|----------|
| **우산 등록 개념** | 논문작성계획서, 예비논문, 본논문 등 큰 카테고리 내에서 세부 단계 등록 가능 | 카테고리별로 신청은 1회씩만, 세부 n차 단계별로 제출과 심사는 반복 가능 | ✅ **전면 수용** |
| **심사 유형 정의** | 각 단계별로 지도교수 단독 심사인지, 심사위원회 심사인지 정의 필요 | `evaluationType` 필드 추가<br>- `advisor_approval`: 지도교수 단독<br>- `committee_evaluation`: 심사위원회 | ✅ **전면 수용** |
| **평가표 적용** | 모든 지도단계에 평가표 적용 | 모든 단계에 심사 프로세스 적용 (단, 지도교수 단독 심사 시 승인 UI 사용) | ✅ **전면 수용** (구현 방식 변경) |

**확인필요사항:**
- 지도교수 1인 평가 or 심사위원회 평가 둘 중 하나의 케이스만 존재하는지 (제 3의 케이스가 더 있는지 확인)

**회의록 + 메일 근거:**
- 메일: "해당 단계의 심사자(지도교수, 심사위원회)가 직접 평가 수행"
- 회의록: "최종이라는 단계 있잖아요. 걔를 제외한 나머지는 사실상 지도교사 다 한다"

**구현 방향:**
- 중간 단계: 지도교수 단독 심사 → 승인 UI (합격/불합격 + 코멘트)
- 최종 단계: 심사위원회 → 평가표 UI

### 1.8 심사위원배정

| 항목 | 논의 내용 | 구현 방안 | 수용 여부 |
|------|----------|----------|----------|
| **지도교수 단독 케이스** | 지도교수 단독으로 심사위원장을 겸하는 경우 고려 | 심사위원 추가 UI 변경<br>심사위원장 선택값을 옵션화 | ❌ **수용 불가** |
| **대안: 심사 유형 분리** | 지도교수 단독 심사 vs 심사위원회 심사 | 지도교수 단독 심사 단계에서는 심사위원 배정 불필요<br>`evaluationType='advisor_approval'` 단계는 심사위원 배정 화면에서 제외 | ✅ **대안 수용** |
| **심사위원 재사용** | 예비심사 N차, 본심사 N차는 기존 구성 내역 재사용 | 기존 구성 내역을 불러와 적용, 필요 시 일부 변경 가능 | ✅ **전면 수용** |

**메일 근거:**
- "프로포절과 예비심사 각각 구성 가능"
- "예비심사 N차, 본심사 N차는 기존 구성 내역 재사용 가능"

**수용 불가 이유:**
- 지도교수 단독 심사 시 심사위원회 구성 자체가 불필요
- 심사위원장/심사위원 구분이 아닌, 심사 유형(지도교수 단독 vs 심사위원회)으로 구분하는 것이 더 명확

### 1.11 논문 심사(단계별 산출물 심사)

| 항목 | 논의 내용 | 구현 방안 | 수용 여부 |
|------|----------|----------|----------|
| **탈락/보완 프로세스** | 현재 탈락/보완 프로세스 불명확 | 조건부합격 프로세스 추가 | ✅ **전면 수용** |
| **재심 프로세스** | 재심시, 기존 논문지도단계 자체는 수정하지 않고, 단계 내에서 재심 실시 | 동일 단계 내 재심 프로세스 구현<br>재제출 UI 명확화, 심사 화면에 재제출 여부 표시 | ✅ **전면 수용** |
| **부속서류 제출** | 재제출 시 논문 파일 이외 논문 부속서류 업로드 | 부속서류 업로드 기능 구현 | ✅ **전면 수용** |
| **재심 방식** | 보완 후 재제출 시 서면평가 vs 심사위원회 전체 재심사 | 재심 방식 선택 기능 추가<br>- 재심(대면): 대면 일정, 심사위원회 전체<br>- 재심(서면): 심사위원장 또는 지도교수 위임 | ⚠️ **부분 수용** - 서면평가 제외 |

**시나리오 문서 결론:**
- "보완후 재제출 시, 동일 심사 프로세스 재 실행 (서면평가 대체까지 구현은 난이도 높아 제외의견)"

**메일 요구사항:**
- "재심(서면): 심사위원장이 승인, 지도교수에게 위임하여 승인할 수 있음"

**최종 구현 방향:**
- Phase 1: 재심(대면) 프로세스만 구현
- Phase 2 이후: 재심(서면) 및 지도교수 위임 기능 검토

## 5. 회의록/메일에서 추가 요청된 사항 (시나리오 문서에 없음)

- "학생처럼 그 플로우가 있는 거를 교수한테도... 학생별로 보여주자는 건데"

## 6. 수용 여부 요약

### ✅ 전면 수용 (구현 확정)

1. **평가표 다양화** - 서술형, 척도형 평가 추가
2. **우산 등록 개념** - 카테고리 내 세부 단계 등록
3. **심사 유형 정의** - evaluationType 필드 추가 (지도교수 단독 vs 심사위원회)
4. **학기 개념 도입** - semester 필드 추가
5. **심사위원 재사용** - 기존 구성 내역 불러오기
6. **부속서류 제출** - 논문 + 부속서류 동시 업로드
7. **조건부합격 프로세스** - 재심 방식(대면) 구현
8. **재심 프로세스** - 동일 단계 내 재심, 재제출 UI 명확화
9. **거절 이력 관리** - 실시간지도 거절 이력 저장
10. **자동 완료처리** - 실시간지도 자동 완료
11. **단계 정보 저장** - 피드백 작성 시점 단계 정보 저장
12. **학생 영역지정 기능** - 학생도 PDF 영역지정 피드백 가능
13. **플로우 시각화** - 학생/교수 화면에 플로우 시각화
14. **메뉴 구조 개선** - 학생/교수 메뉴 구조 개선
15. **관리자 화면 개선** - 단계별 통합 조회

## 9. 용어 정리

### 9.1 심사 vs 승인

| 용어 | 대상 | 의미 | 사용 화면 |
|------|------|------|----------|
| **제출** | 학생 | 모든 산출물 제출 | 학생 화면 |
| **심사** | 교수 (최종 단계) | 심사표 기반 정식 평가 (심사위원회) | 교수 화면 (최종 단계) |
| **승인** | 교수 (중간 단계) | 합격/불합격 + 코멘트로 단계 진행 (지도교수) | 교수 화면 (중간 단계) |

---

### 9.2 불합격 vs 조건부합격

| 용어 | 의미 | 다음 단계 진행 | 재심 |
|------|------|--------------|------|
| **합격** | 통과 | ✅ 가능 | ❌ 불필요 |
| **조건부합격** | 수정 보완 필요 | ✅ 가능 (재심 후) | ✅ 필수 |
| **불합격** | 해당 단계 종결 | ❌ 불가 (다음 학기 재신청) | ❌ 불가 |

**예외 (중간 단계 운영):**
- 중간 단계에서는 교수 판단으로 불합격이어도 코멘트 남기고 다음 단계 이동 가능
- 정책적 과제: 교학팀의 안내 및 설득 필요

---

### 9.3 재심 방식

| 재심 방식 | 설명 | 대상 단계 | Phase |
|----------|------|----------|-------|
| **재심(대면)** | 대면 일정 지정, 심사위원회 전체 심의 | 모든 단계 | Phase 1 |
| **재심(서면)** | 논문 제출 기간 설정, 심사위원장 또는 지도교수 위임 승인 | 석사 본심, 박사 본심 2차 | Phase 2 |
