## 논문 지도단계 부여 - 수행 - 승급 프로세스
# 단계지도유형관리 등록
- 관리자화면
- 담당: 대학원 본부
- 유형은 논문작성계획서, 예비심사, 본심사의 틀을 벗어나지 않음
- 위 유형들은 반드시 필요하고, 이 단계 내에서 세부 유형을 등록함(학과마다 이름만 다르게 쓰도록)

# 각 단계별 심사평가기준 등록
- 관리자화면
- 담당: 대학원 본부
- 각 단계별로 적용된 심사평가기준표 구성(점수형, P/F형 등)
(*) 문제점
- 서술형 평가 등 등록 요청

# 지도단계등록
- 관리자화면
- 담당: 대학원 전공 - 학과 조교
- 학과별도지도단계 등록 시, 학과정보등록
- 반드시, 학과별로 유효한 학위논문 / 학술지논문 지도단계 1개씩 식별하여 등록
- 각 단계별로 적용될 심사평가기준표 사전 매핑
- 학과별로 학위논문/학술지논문 심사 대상인지는 매 학기초에 반영
(*) 문제점
- 이 단계에서 심사 유형을 지도교수가 한번에 심사하거나, 심사위원회를 통할 것인지 정의해야 하는지 확인 필요

# 지도단계별 일정 등록
- 관리자 화면
- 담당: 대학원 전공 - 학과 조교
- 지도단계 등록 시 설정한 일정 유형에 따라 일정 등록

# 지도교수-학생 배정 및 등록
- 관리자 화면
- 담당: 기간계 시스템에서 수행. 대학원 전공 - 학과 조교가 입력 

# 지도교수-학생정보 배치
- 관리자 화면
- 담당: 논문지도시스템
- 일 배치 시행, 논문지도시스템 이용대상 이용자 정보 인입

# 학생 - 지도단계 부여
- 관리자 화면
- 담당: 논문지도시스템 / 대학원 전공 - 학과 조교
- 학과별로 지정된 유효 지도단계와 학생을 매핑 - 배정
- 학과별로 지정된 유효 지도단계가 없는 경우, 학생은 미배정상태가 됨
- 미배정학생 또는 별도의 필요에 의해 시스템 내에서 학과 담당자가 학생의 지도단계를 신규 부여하거나 수정 실시

# 심사위원배정
- 관리자화면
- 담당: 대학원 전공 - 학과 조교
- 각 학생별로 심사위원을 조회 - 배정하여 심사위원회를 구성함
(*) 문제점
- 학교측 요구사항 수용을 위해서는 지도교수 단독으로 심사위원장을 겸하는 경우가 생겨야하지만, 이 케이스가 고려되어 있지 않음
- 심사위원배정 시, 심사위원풀에서 심사위원장을 필수값으로하고, 심사위원을 옵션으로 변경하면 해결되는지 확인

# 심사신청
- 학생용화면
- 담당: 학생이 본인이 심사받을 논문정보를 등록함(승인 신청)
- 학위논문 심사를 신청. 여기서의 신청이란 각 단계의 신청이 아니라 학위논문 플로우 자체를 신청하는 것에 가까움
(*) 문제점
- 현재 시스템상으로는 각 단계별로 신청이 있기 때문에, 신청-제출-심사를 반복해야함
- 학과별로 세부단계의 일정을 정하더라도 실제 교수-학생이 이를 따르지 않는 경우가 많을 것(현실세계 업무와 괴리)으로 예상
- 학교의 니즈는 교수가 학생의 지도단계를 확인하고 승급처리하게끔 하는 것이므로 각 단계의 신청-승인을 위해서라도 지금 구조 유지는 필요

# 논문 제출(단계별 산출물 제출)
- 학생용화면
- 담당: 지도학생
- 교수에게 승인을 요청하는 산출물을 시스템에 등록

# 논문 심사(단계별 산출물 제출)
- 교수용화면
- 담당: 지도교수(혹은 심사위원)
- 학생이 등록한 심사대상 산출물을 보고 심사 - 평가
- 지도교수 단독평가 혹은 심사위원회 평가
- 심사위원회 평가 시, 탈락 혹은 보완후 재제출 프로세스 보완
(*) 문제점
- 현재 탈락 / 보완 프로세스 불명확
- 탈락: 탈락 시, 다음 학기에 탈락한 시점부터 논문 신청 등 재 시작
- 보완 후 재제출: 심사위원장 결정에 따라 심사위원장의 서면평가-업로드 후 통과 or 심사위원회 전체 재심사 케이스로 분기

# 논문지도단계 승급(현재 진행중인 단계 종결)
- 교수용 화면
- 담당: 지도교수 혹은 심사위원회 소속 교수
- 학생이 등록한 산출물을 교수가 '통과'처리한 경우, 해당 지도단계를 완료할 것으로 간주

## 학기별 논문지도계획 작성 - 승인 프로세스
# 학기별 논문지도계획 작성
- 학생용 화면
- 담당: 지도학생
- 학기별지도계획을 새로 생성 - 계획을 입력하고 승인 신청

# 학기별 논문지도계획 승인
- 교수용 화면
- 담담: 지도교수
- 학기별지도계획 확인-수정 및 승인
- 승인취소 프로세스 없음. 승인 이후에는 계획 수정 불가

## 실시간 지도예약 프로세스
# 실시간지도 가능 시간 등록
- 교수용 화면
- 담당: 지도교수
- (지도예약 가능 일정등록 시) 본인이 미팅 가능한 일정 슬롯 등록(최대 120분)
- (지정형일 경우), 본인이 지도하고자하는 학생 정보를 검색하여, 일정 등록

# 실시간지도 신청
- 학생용 화면
- 담당: 지도학생
- 교수가 사전에 설정한 일정 슬롯 중, 본인이 원하는 일정을 선택하여 지도 예약을 신청함 

# 실시간지도 승인
- 교수용 화면
- 담당: 지도교수
- 학생이 신청한 지도예약을 승인 또는 거절. 거절 시, 거절 사유 입력. 거절 일정은 다시 일정 가능한 슬롯으로 복구

# 줌 예약 활성화
- 교수용화면, 학생용화면
- 담당: 논문지도시스템
- 온라인 실시간지도예약이 승인되었을 시, 줌 미팅을 생성하고 줌 미팅 주소를 반환하여 시스템에 출력
- 교수에게는 줌 미팅 정상 생성 - 학생에게 알림이 발송된다는 사항 확인

# 완료일정 관리
- 교수용화면, 학생용화면
- 담당: 논문지도시싀템
- 완료된 온라인 미팅 영상은 줌 클라우드에 저장 - 다운로드 혹은 플레이어 호출 처리
(*) 문제점
- 완료된 일정은 별도의 완료처리 없도록 처리(현재 시스템에는 완료처리하도록 강제)

## 논문지도활동 프로세스
# 논문지도대상(피드백 대상) 파일 등록 
- 학생용 화면
- 담당: 지도학생
- 학생이 피드백 대상 파일을 시스템에 게시 
- 업로드 시,  해당 학생의 지도단계를 기본값으로 등록할 수 있도록 설정 (변경 가능)
- 논문지도활동은 지도교수만 매핑되어있다면 언제든 업로드할 수 있도록 처리
(*) 문제점
- 학생이 교수가 아직 피드백을 남기지 않은 파일은 수정할 수 있어야 함
- 교수가 피드백을 남기는 도중에 파일이 교체되는 이슈가 있으므로, 열람건수를 기준으로 0일 때에만 수정 가능하도록 처리

# 논문지도 대상 확인 및 피드백
- 교수용화면
- 담당: 지도교수
- 학생이 업로드한 PDF 파일 확인하고, 판서 및 영역 지정을 통해 피드백 기재

# 학생의 파일 업로드
- 학생용화면
- 담당: 지도학생
- 지도교수가 남긴 피드백 내용을 확인하고., 해당 내용을 적용한 PDF파일을 재업로드 
(*) 문제점
- 본 시스템은 매번 새로운 파일을 업로드하도록 하고 있는데, 이전 버전에 남긴 피드백과 새로 업로드하는 문서 내 피드백을 매핑할 방법이 없음
- 대안으로 학생이 문서를 업로드한 후, 영역 지정 기능을 통해 교수의 피드백 반영 내용을 표시할 수 있도록 함(현재는 학생은 댓글만 게시 가능함)
