## 1. 심각한 충돌 (🔴 High Priority)

### 1.1 심사위원 구성 방식

#### 시나리오 문서
> **심사신청** (Line 55-63)
> - 학위논문 심사를 신청. 여기서의 신청이란 각 단계의 신청이 아니라 **학위논문 플로우 자체를 신청**하는 것에 가까움
>
> **(*) 문제점**
> - 현재 시스템상으로는 각 단계별로 신청이 있기 때문에, 신청-제출-심사를 반복해야함

> **심사위원배정** (Line 47-54)
> - 각 학생별로 심사위원을 조회 - 배정하여 심사위원회를 구성함
>
> **(*) 문제점**
> - 학교측 요구사항 수용을 위해서는 **지도교수 단독으로 심사위원장을 겸하는 경우**가 생겨야하지만, 이 케이스가 고려되어 있지 않음
> - 심사위원배정 시, 심사위원풀에서 심사위원장을 필수값으로하고, **심사위원을 옵션으로 변경**하면 해결되는지 확인

#### 회의록 + 메일
> **메일 원문:**
> 1. 심사주체
> 1) 해당 단계의 심사자(단계에 따라 **지도교수, 심사위원회**)가 직접 평가 수행
> 예. 논문작성계획서 – **지도교수**
> 석사 예비심사 - **지도교수 또는 예비심사위원회**
> 박사 예비심사 – **예비심사위원회**

> **회의록 원문:**
> "최종이라는 단계 있잖아요. 걔를 제외한 나머지는 사실상 **지도교사 다 한다**라는 거잖아요."

#### 충돌 내용 및 해결 (✅ 확인 완료)
**🔴 심각한 충돌:**

1. **시나리오**: 모든 단계에서 "심사위원회 구성" → "심사위원 배정" 필요
2. **회의록 + 메일**: 중간 단계는 **지도교수 단독 심사**, 최종 단계만 심사위원회 구성

**✅ 사용자 확인 (2026.01.26):**
> "모든 단계에 **심사**가 필요한 것이지, **심사위원 배정**이 필요하다는 의미가 아니다. 심사 자체를 할 수 있게 하되, 어떤 단계는 심사위원회가 필요하다는 의미이다."

**최종 해결 방안:**
- 지도단계 등록 시 `evaluationType` 필드 추가
  - `advisor_approval`: 지도교수 단독 심사 (심사위원 배정 불필요)
  - `committee_evaluation`: 심사위원회 심사 (심사위원 배정 필수)
- 심사위원 배정 화면: `evaluationType='committee_evaluation'`인 단계만 표시
- 지도교수 단독 심사 시:
  - 심사위원장 = 지도교수 (자동 매핑)
  - 평가표 대신 승인 프로세스 (합격/불합격 선택 + 코멘트)

**수정 공수:**
- DB 스키마 변경: ThesisStage 테이블에 `evaluationType` 컬럼 추가
- 심사위원 배정 화면 수정: 조건부 표시 (committee_evaluation만)
- 심사 평가 화면 분기: advisor_approval → 승인 UI, committee_evaluation → 평가표 UI
- **예상 공수: 3일**

### 1.2 불합격 처리 프로세스

#### 시나리오 문서
> **논문 심사** (Line 69-79)
> **(*) 문제점**
> - 현재 **탈락 / 보완 프로세스 불명확**
> - **탈락**: 탈락 시, 다음 학기에 탈락한 시점부터 논문 신청 등 재 시작
> - **보완 후 재제출**: 심사위원장 결정에 따라 심사위원장의 서면평가-업로드 후 통과 or 심사위원회 전체 재심사 케이스로 분기

#### 메일
> **3. 조건부합격 처리 프로세스 추가 요청**
> **불합격은 해당 단계에서 종결, 다음단계 미진행**
> 수정 보완해서 다음 단계 진입이 가능한 경우 **조건부합격을 활용**하라는 가이드를 행정에서 안내

#### 회의록
> "불합격해도 뒤로는 넘겨야 되잖아요"
> "그거는 코멘트를 남겨놓고 일단 단계 그건 레이블을 좀 고민해 봐야겠지만 거기다가 기록을 남기게끔"

#### 충돌 내용
**🔴 심각한 충돌:**

1. **시나리오**:
   - "탈락" = 불합격 → 다음 학기 재시작
   - "보완 후 재제출" = 조건부합격과 유사하지만 용어 다름

2. **메일 (원칙)**:
   - 합격 / **조건부합격** / 불합격
   - 불합격 = 해당 단계에서 종결
   - 조건부합격 = 재심 프로세스

3. **회의록 (운영)**:
   - 중간 단계에서는 불합격이어도 교수 판단으로 다음 단계 이동 가능

**용어 정리 필요:**
- ❌ "탈락" → ✅ "불합격"
- ❌ "보완 후 재제출" → ✅ "조건부합격 → 재심"

**해결 방안:**

**A. 평가 결과 3가지로 통일**
```
합격 → 다음 단계 이동
조건부합격 → 재심 프로세스 (같은 단계 유지)
  - 재심(대면): 심사위원(장) 재심의
  - 재심(서면): 심사위원장 또는 지도교수 위임
불합격 → 해당 단계에서 종결
  - 최종 단계: 다음 학기 재신청 필요
  - 중간 단계: 교수 판단으로 다음 단계 이동 가능 (코멘트 기록)
```

**B. 데이터 구조**
```javascript
ExaminationHistory {
  examRound: 1,
  result: 'pass' | 'conditional_pass' | 'fail',
  reexamInfo: {
    method: '대면' | '서면',
    evaluationType: 'full' | 'chair_only' | 'advisor_delegated',
    deadline: Date,
    requirements: String
  }
}
```

**수정 공수:**
- UI 변경: "탈락" → "불합격", "보완" → "조건부합격" 용어 통일
- ExaminationHistory 테이블 생성
- 재심 프로세스 구현 (재심사_구현방식_최종.md 참조)
- **예상 공수: 5일**

### 1.3 심사 평가 기준표 vs 승인 프로세스

#### 시나리오 문서
> **각 단계별 심사평가기준 등록** (Line 9-15)
> - 각 단계별로 적용된 **심사평가기준표 구성**(점수형, P/F형 등)
>
> **(*) 문제점**
> - **서술형 평가** 등 등록 요청

> **지도단계등록** (Line 16-25)
> - 각 단계별로 적용될 **심사평가기준표 사전 매핑**
>
> **(*) 문제점**
> - 이 단계에서 **심사 유형을 지도교수가 한번에 심사하거나, 심사위원회를 통할 것인지 정의**해야 하는지 확인 필요

#### 메일
> **4. 평가표 추가**
> - **서술형 평가** 추가: 심사자 서술형 의견 입력
> - **척도형 평가** 추가 (붙임의 평가표 양식참조 / 현재 사용중인 양식)

#### 회의록
> "심사표 없을 때... 여기서 산출물 보고 여기서 **승인 처리**해서 승인되면은 상태 값이 승인으로 바뀌고"
> "승인 버튼을 두고 옆에다가 얘는 **합격 불합격 하나** 이제 선택할 수 있는 값을 두고"

#### 충돌 내용
**🔴 심각한 충돌:**

1. **시나리오**: 모든 단계에 "심사평가기준표" 사전 매핑 필요
2. **회의록 + 메일**:
   - 중간 단계: 평가표 없이 **승인 프로세스** (합격/불합격 선택)
   - 최종 단계: 서술형 + 척도형 평가표

**해결 방안:**

**A. 평가 방식 구분**
```javascript
ThesisStage {
  stages: [
    {
      order: 1,
      name: '논문작성계획서',
      evaluationType: 'advisor_approval',  // 지도교수 승인
      evaluationForm: null,                 // 평가표 없음
      approvalRequired: true                // 승인 필요
    },
    {
      order: 2,
      name: '본심사 최종',
      evaluationType: 'committee_evaluation', // 심사위원회 평가
      evaluationForm: 'FORM_001',            // 서술형 + 척도형 평가표
      approvalRequired: false
    }
  ]
}
```

**B. 관리자 화면 수정**
- 지도단계 등록 시:
  - evaluationType 선택 필수
  - `advisor_approval` → 평가표 매핑 불필요 (승인만)
  - `committee_evaluation` → 평가표 매핑 필수

**수정 공수:**
- 지도단계 등록 UI 수정
- 평가표 매핑 로직 조건부 처리
- 교수 평가 화면 분기 처리 (승인 vs 평가표)
- **예상 공수: 3일**
