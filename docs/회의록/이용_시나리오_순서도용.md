# 1. 시스템 초기 설정 프로세스

## 1.1 단계지도유형 관리 등록

**담당:** 대학원 본부 (관리자)

```
시작
  ↓
[관리자] 단계지도유형 관리 화면 접속
  ↓
[관리자] 유형 등록
  - 논문작성계획서
  - 예비심사
  - 본심사
  ↓
각 유형별 세부 유형 등록
  - 학과마다 이름 다르게 사용 가능
  ↓
저장
  ↓
종료
```

**비고:**
- 논문작성계획서, 예비심사, 본심사는 필수 유형
- 세부 유형은 학과별로 커스터마이징 가능

---

## 1.2 심사평가기준 등록

**담당:** 대학원 본부 (관리자)

```
시작
  ↓
[관리자] 심사평가기준 관리 화면 접속
  ↓
평가표 유형 선택
  ├─ 서술형 평가
  │   ├─ 심사자 의견 입력 필드 설정
  │   └─ 종합평정 책임자 설정 (지도교수 or 심사위원장)
  │
  └─ 척도형 평가
      ├─ 평가 항목 입력 (연구목적, 방법론, 결과 등)
      ├─ 항목별 배점 설정
      └─ 자동 합산 설정
  ↓
평가표 템플릿 저장
  ↓
종료
```

**확인 필요:**
- 척도형 평가 양식의 정확한 항목 및 배점 (현재 사용 중인 양식 요청)

---

## 1.3 지도단계 등록 (학과별)

**담당:** 대학원 전공 - 학과 조교 (관리자)

```
시작
  ↓
[학과 조교] 지도단계 등록 화면 접속
  ↓
학과 정보 선택
  ↓
학위논문 / 학술지논문 구분
  ↓
각 단계별 정보 입력
  ├─ 단계명
  ├─ 단계 순서 (order)
  ├─ 단계 유형 (논문작성계획서 / 예비심사 / 본심사)
  ├─ 평가 방식 선택 ✨ 핵심
  │   ├─ advisor_approval (지도교수 승인)
  │   │   ├─ 심사위원 배정 불필요
  │   │   └─ 평가표 매핑 불필요
  │   │
  │   └─ committee_evaluation (심사위원회 평가)
  │       ├─ 심사위원 배정 필수
  │       └─ 평가표 매핑 필수 → 평가표 선택
  │
  ├─ 재심 허용 여부
  └─ 불합격 시 진행 허용 여부
  ↓
[시스템] 학과별 유효 지도단계 1개 식별
  - 학위논문용 1개
  - 학술지논문용 1개
  ↓
저장
  ↓
종료
```

**핵심 결정:**
- **중간 단계**: advisor_approval → 지도교수 단독 승인
- **최종 단계**: committee_evaluation → 심사위원회 평가

```
  ↓
```

## 1.5 지도교수-학생 배정

**담당:** 기간계 시스템 → 논문지도시스템 배치

```
시작
  ↓
[기간계 시스템] 지도교수-학생 배정 정보 생성
  - 대학원 전공 - 학과 조교가 입력
  ↓
[논문지도시스템] 일 배치 실행
  ↓
지도교수-학생 정보 인입
  ↓
학생-지도단계 자동 배정
  ├─ 학과별 유효 지도단계 존재 시
  │   └─ 자동 배정
  │
  └─ 유효 지도단계 없을 시
      └─ 미배정 상태
  ↓
StudentThesisStage 생성
  - studentId
  - advisorId
  - currentStageOrder = 1 (시작 단계)
  - semester (현재 학기)
  - enrollmentSemester (최초 배정 학기)
  - isExtended = false
  - canProceed = true
  ↓
종료
```

**핵심:**
- 지도교수 배정은 졸업 전까지 연속성 유지
- 학생이 졸업하거나 변경 신청하기 전까지 자동 연장

## 1.6 심사위원 배정 (최종 단계만)

**담당:** 대학원 전공 - 학과 조교 (관리자)

```
시작
  ↓
[학과 조교] 심사위원 배정 화면 접속
  ↓
[시스템] evaluationType = 'committee_evaluation'인 단계만 표시
  ↓
학생 선택
  ↓
단계 선택 (예비심사, 본심사 등)
  ↓
기존 구성 불러오기 여부 확인
  ├─ 예 → 이전 단계 심사위원 구성 조회
  │         └─ 불러온 구성에서 일부 변경 가능
  │
  └─ 아니오 → 신규 구성
      ├─ 심사위원장 선택 (필수)
      └─ 심사위원 선택 (옵션)
  ↓
CommitteeAssignment 저장
  - chair (심사위원장)
  - members (심사위원들)
  - previousAssignmentId (이전 구성 참조)
  ↓
종료
```

**핵심:**
- 프로포절과 예비심사는 각각 별도 구성 가능
- 예비심사 N차, 본심사 N차는 기존 구성 재사용 가능

# 3. 논문 지도단계 수행 프로세스 (핵심)

## 3.1 학생 - 논문 제출

```
시작
  ↓
[학생] 대시보드에서 현재 단계 확인
  - 플로우 시각화로 진행 상황 파악
  ↓
[학생] 학위 논문 제출 메뉴 접속
  ↓
[학생] 단계 유형 선택
  - 논문 작성 계획서
  - 예비 심사
    - 1차
    - 2차
    - 3차
  - 본 심사
    - 1차
    - 2차
  ↓
[학생] 제출 유형 확인
  ├─ 초기 제출
  │   ├─ 논문 파일 업로드 (필수)
  │   └─ 부속서류 업로드 (선택)
  │
  └─ N차 제출 또는 재심 제출
      ├─ 수정 논문 업로드 (필수)
      └─ 수정전후대비표 등 부속서류 업로드 (필수)
  ↓
GuidanceSubmission 생성
  - mainFile (주 논문 파일)
  - attachments (부속서류)
  - version (버전 번호)
  - previousSubmissionId (이전 제출물 참조)
  - stageAtSubmission (제출 당시 단계)
  ↓
[시스템] 지도교수 또는 심사위원에게 알림 발송
  ↓
종료
```

**핵심:**
- 메뉴 구조: 단계 유형 → 세부 단계로 계층 구조
- N차 제출, 재심 제출 시 부속서류 필수

## 3.3 교수 - 심사/승인 처리 (분기점 ✨)

### 3.3.1 중간 단계 - 지도교수 단독 승인

```
시작
  ↓
[교수] 심사 평가 메뉴 접속
  ↓
[시스템] evaluationType = 'advisor_approval' 단계 표시
  ↓
[교수] 학생 선택
  ↓
[교수] 제출물 확인
  ↓
[교수] 승인 처리 화면
  ↓
평가 결과 선택
  ├─ 합격
  │   ├─ [교수] 코멘트 작성 (선택)
  │   ├─ [교수] 승인 버튼 클릭
  │   ├─ [시스템] 다음 단계로 자동 이동
  │   │   └─ StudentThesisStage.currentStageOrder += 1
  │   └─ [시스템] 학생에게 합격 알림
  │
  ├─ 불합격
  │   ├─ [교수] 코멘트 작성 (필수)
  │   ├─ 다음 단계 이동 여부 선택 ⚠️
  │   │   ├─ "승인 및 다음 단계 이동" 체크
  │   │   │   ├─ [시스템] 불합격 기록 + 코멘트 저장
  │   │   │   ├─ [시스템] 다음 단계로 이동
  │   │   │   └─ [시스템] 학생에게 알림 (불합격이지만 진행)
  │   │   │
  │   │   └─ 체크하지 않음
  │   │       ├─ [시스템] 불합격 기록 + 코멘트 저장
  │   │       ├─ [시스템] 단계 유지 (currentStageOrder 변경 없음)
  │   │       └─ [시스템] 학생에게 불합격 알림
  │   │
  │   └─ 🔶 운영 가이드: 교수에게 "조건부합격" 사용 권장
  │
  └─ 조건부합격 ✨
      └─ → [3.4 조건부합격 및 재심 프로세스]로 이동
  ↓
종료
```

**정책적 충돌 지점:**
- **원칙 (메일)**: 불합격 → 단계 종결
- **운영 (회의)**: 교수 판단으로 불합격이어도 다음 단계 이동 가능
- **해결**: 시스템은 두 옵션 모두 제공, 운영 가이드로 조건부합격 사용 권장

**확인 필요:**
- Option A (원칙 준수) vs Option B (유연한 운영) 중 최종 선택

---

### 3.3.2 최종 단계 - 심사위원회 평가

```
시작
  ↓
[심사위원] 심사 평가 메뉴 접속
  ↓
[시스템] evaluationType = 'committee_evaluation' 단계 표시
  ↓
[심사위원] 학생 선택
  ↓
[심사위원] 제출물 확인
  ↓
[심사위원] 평가표 작성
  ├─ 서술형 평가
  │   ├─ 각 심사위원이 서술형 의견 입력
  │   └─ 심사위원장이 종합평정 작성
  │
  └─ 척도형 평가
      ├─ 각 항목별 점수 입력
      └─ [시스템] 자동 합산
  ↓
[심사위원장] 심사위원회 전체 평가 결과 취합
  ↓
평가 결과 선택
  ├─ 합격
  │   ├─ ExaminationHistory 저장
  │   │   - examRound = 1 (초기 심사)
  │   │   - examType = 'initial'
  │   │   - result = 'pass'
  │   ├─ [시스템] 다음 단계로 자동 이동
  │   └─ [시스템] 학생에게 합격 알림
  │
  ├─ 조건부합격 ✨
  │   └─ → [3.4 조건부합격 및 재심 프로세스]로 이동
  │
  └─ 불합격
      ├─ ExaminationHistory 저장
      │   - examRound = 1
      │   - examType = 'initial'
      │   - result = 'fail'
      ├─ [시스템] 단계 종결
      ├─ 재신청 안내
      │   └─ StudentThesisStage 업데이트
      │       - needsReapplication = true
      │       - canProceed = false
      └─ [시스템] 학생에게 불합격 알림
          └─ → [4. 재신청 프로세스]로 이동
  ↓
종료
```

**핵심:**
- 심사위원 + 심사위원장 모두 반드시 평가표 작성
- 최종 단계 불합격 시 재신청 프로세스 시작

## 3.4 조건부합격 및 재심 프로세스 ✨

### 3.4.1 조건부합격 판정 및 재심 정보 설정

```
시작 (3.3.1 또는 3.3.2에서 조건부합격 선택)
  ↓
[심사위원장 또는 지도교수] 조건부합격 선택
  ↓
[시스템] 재심 정보 설정 모달 표시
  ↓
[심사위원장] 재심 방식 선택
  ├─ 재심(대면)
  │   ├─ 대면 일정 선택 (Datepicker)
  │   ├─ 심사 장소 입력
  │   ├─ 보완 요구사항 입력 (Textarea)
  │   └─ [시스템] evaluationType 자동 설정
  │       └─ evaluationType = 'full' (전체 심사위원 평가)
  │
  └─ 재심(서면)
      ├─ 논문 제출 기한 선택 (Datepicker)
      ├─ 보완 요구사항 입력 (Textarea)
      ├─ 평가자 선택 ⚠️
      │   ├─ 심사위원장만 평가
      │   │   └─ evaluationType = 'chair_only'
      │   │
      │   └─ 지도교수에게 위임
      │       └─ evaluationType = 'advisor_delegated'
      │       └─ delegatedTo = advisorId
      │
```

## 3.5 석사 vs 박사 재심 프로세스 차이

### 3.5.1 석사 본심사 재심

```
본심사 평가
  ├─ 합격 → 최종합격
  ├─ 조건부합격 → 재심
  │   ├─ 재심(대면) → 합격 → 최종합격
  │   │              └─ 불합격 → 다음학기 본심 재신청
  │   │
  │   └─ 재심(서면) → 합격 → 최종합격
  │                  └─ 불합격 → 다음학기 본심 재신청
  │
  └─ 불합격 → 최종 불합격 (다음학기 재신청)
```

---

### 3.5.2 박사 본심사 재심 (2회)

```
본심사 1차
  ├─ 합격 → 본심사 2차 진행
  ├─ 조건부합격 → 본심사 2차 진행 (2차에서 보완 재심사)
  └─ 불합격 → 본심사 2차 불가 (다음학기 본심사 재신청)
      ↓
본심사 2차 (최종)
  ├─ 합격 → 최종합격
  ├─ 조건부합격 → 재심(서면)
  │   ├─ 심사위원장이 재심사 논문제출 기간 설정
  │   ├─ 합격 → 최종합격
  │   └─ 불합격 → 다음학기 본심사 재진행
  │
  └─ 불합격 → 다음학기 본심사 재진행
```

**핵심:**
- 박사 본심사 1차 조건부합격자는 2차에서 재심
- 박사 본심사 2차 조건부합격은 서면 재심만

# 10. 주요 분기점 및 결정 사항 요약

## 10.1 평가 방식 분기 (evaluationType)

```
지도단계 등록 시 evaluationType 설정
  ├─ advisor_approval (중간 단계)
  │   ├─ 심사위원 배정: 불필요
  │   ├─ 평가표: 불필요
  │   ├─ 승인 방식: 합격/불합격 + 코멘트
  │   └─ 예시: 논문작성계획서, 석사 예비심사 등
  │
  └─ committee_evaluation (최종 단계)
      ├─ 심사위원 배정: 필수
      ├─ 평가표: 필수 (서술형/척도형)
      ├─ 평가 방식: 심사위원회 평가
      └─ 예시: 박사 예비심사, 석사/박사 본심사 최종
```

---

## 10.2 평가 결과 분기

```
평가 결과 입력
  ├─ 합격
  │   └─ 다음 단계로 이동
  │
  ├─ 조건부합격
  │   └─ 재심 프로세스
  │       ├─ 재심(대면)
  │       │   └─ evaluationType = 'full'
  │       │
  │       └─ 재심(서면)
  │           ├─ evaluationType = 'chair_only'
  │           └─ evaluationType = 'advisor_delegated'
  │
  └─ 불합격
      ├─ 중간 단계
      │   ├─ Option A: 단계 종결 (원칙)
      │   └─ Option B: 교수 판단으로 다음 단계 이동 가능 (운영)
      │
      └─ 최종 단계
          └─ 재신청 프로세스
```

---

## 10.3 재심 방식 분기

```
재심 방식 선택
  ├─ 재심(대면)
  │   ├─ evaluationType = 'full' (전체 심사위원)
  │   ├─ 대면 일정 설정
  │   └─ 대면 심사 진행
  │
  └─ 재심(서면)
      ├─ evaluationType 선택
      │   ├─ chair_only (심사위원장만)
      │   └─ advisor_delegated (지도교수에게 위임)
      │
      └─ 논문 제출 기한 설정
```

---

## 10.4 석사 vs 박사 분기

```
학위 구분
  ├─ 석사
  │   └─ 본심사 1회
  │       └─ 조건부합격 → 재심 → 합격/불합격
  │
  └─ 박사
      └─ 본심사 2회
          ├─ 1차: 합격/조건부합격 → 2차 진행
          │       불합격 → 2차 불가
          │
          └─ 2차: 합격 → 최종합격
                  조건부합격 → 재심(서면)
                  불합격 → 재신청
```

# 12. 데이터 구조 요약

## 핵심 테이블

### ThesisStage (지도단계 등록)
```javascript
{
  stageId: String,
  departmentId: String,
  order: Number,
  name: String,
  stageType: '논문작성계획서' | '예비심사' | '본심사',
  evaluationType: 'advisor_approval' | 'committee_evaluation', // ✨ 핵심
  evaluationForm: String | null,  // 평가표 ID (committee_evaluation일 때만)
  allowReexam: Boolean,            // 재심 허용 여부
  allowFailAndProceed: Boolean     // 불합격 시 진행 허용 여부
}
```

### StudentThesisStage (학생-지도단계 매핑)
```javascript
{
  studentId: String,
  advisorId: String,
  currentStageOrder: Number,       // 현재 진행 단계
  semester: String,                // 현재 활동 학기 (예: 2026-1)
  enrollmentSemester: String,      // 최초 배정 학기
  isExtended: Boolean,             // 학기 연장 여부
  canProceed: Boolean,             // 다음 단계 진행 가능 여부
  needsReapplication: Boolean      // 재신청 필요 여부
}
```

### ExaminationHistory (심사 이력) - 신규
```javascript
{
  id: String,
  studentId: String,
  stageOrder: Number,
  stageName: String,
  examRound: Number,               // 1: 초기, 2: 1차 재심, 3: 2차 재심
  examType: 'initial' | 'reexam',
  result: 'pass' | 'conditional_pass' | 'fail',
  reexamInfo: {                    // 조건부합격일 때만
    method: '대면' | '서면',
    evaluationType: 'full' | 'chair_only' | 'advisor_delegated',
    deadline: Date,
    requirements: String,
    status: 'pending' | 'submitted' | 'completed'
  },
  evaluationDate: Date
}
```

### ThesisApplication (재신청) - 신규
```javascript
{
  id: String,
  studentId: String,
  stageOrder: Number,
  semester: String,
  isReapplication: Boolean,        // 재신청 여부
  previousApplications: [String],  // 이전 신청 ID 배열
  title: String,
  abstract: String,
  keywords: [String],
  committeeChair: String,
  committeeMembers: [String],
  status: 'application_submitted' | 'committee_assigned' |
          'thesis_submitted' | 'exam_scheduled' |
          'under_evaluation' | 'completed' | 'failed'
}
```

### GuidanceSubmission (논문 제출)
```javascript
{
  id: String,
  studentId: String,
  mainFile: String,                // 주 논문 파일
  attachments: [String],           // 부속서류
  title: String,
  stageAtSubmission: Number,       // 제출 당시 단계 ✨
  version: Number,                 // 버전 번호 (Phase 1 또는 3)
  previousSubmissionId: String,    // 이전 제출물 참조 (Phase 1 또는 3)
  viewCount: Number,               // 열람 건수 (수정 가능 여부 판단)
  submittedAt: Date
}
```

### CommitteeAssignment (심사위원 배정)
```javascript
{
  id: String,
  studentId: String,
  stageOrder: Number,
  chair: String,                   // 심사위원장 (필수)
  members: [String],               // 심사위원 (옵션)
  previousAssignmentId: String | null,  // 이전 구성 참조
  assignedAt: Date
}
```
