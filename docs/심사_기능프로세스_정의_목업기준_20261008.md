# 논문 심사 기능 프로세스 정의 (목업 기준)

- 작성일: 2026-10-08 / 갱신: 2026-10-08 (제출취소 삭제 → 신청 철회로 일원화, 재심사 1안·2안, 시연 시나리오 MECE 정리)
- 기준: 현재 배포 목업 https://hycu-new.vercel.app , 기능정의서 v2.7
- 범위: 신청 · 신청 철회 · 제출 · 제출 수정 · 심사(평가 · 판정) · 재심사(조건부합격 보완 / 불합격 후 1안·2안)
- 정의 방법(MECE)
  1. **단위**를 하나로 정함 → 2. **상태**를 겹치지 않게 나눔 → 3. **기능**을 주체별로 빠짐없이 나열 → 4. **상태 × 기능** 표로 모든 경우의 허용·차단을 정함 → 5. 재심사는 별도 기능이 아니라 위 기능의 **경로**로 정의 → 6. 시연 시나리오는 상태 1개당 1개

## 1. 단위: 심사 건

- **심사 건 = 학생 1명 + 기본단계 1개** (논문작성계획서 / 예비심사 / 본심사)
- 한 심사 건 안에서 제출·심사할 때마다 **차수**가 1씩 늘어남 (1차, 2차 …). 조건부합격 보완이든 불합격 후 재심사든 같음
- 목록은 심사 건마다 1행(최신 차수). 상세 화면에 '1차 제출', '2차 제출'…(학생) / '1차 심사', '2차 심사'…(교수) 순서로 전부 표시
- 이전 기본단계 결과는 다른 심사 건이므로 영향 없음

## 2. 핵심 규칙

| 규칙 | 내용 |
|---|---|
| R1 제출 삭제 | 별도의 제출취소는 없음. 제출 자료는 **신청 철회로만** 삭제 (신청과 그 신청의 제출이 함께 삭제) |
| R2 철회 불가 | 같은 신청 안에 **심사 내역**(심사위원 평가 저장 1건 이상, **임시저장 포함**) 또는 판정 결과가 있으면 철회 불가 |
| R3 철회 안내 | 제출 내역이 있으면 "제출한 심사자료가 있습니다…" 문구, 없으면 요구서 문구로 확인 |
| R4 불합격 학기 | 불합격 처리된 학기에는 같은 단계를 다시 진행할 수 없음 (1안: 제출 차단 / 2안: 신청 차단) |
| R5 재심사 안 | 불합격 후 처리 방식은 **1안(신청 유지)** 또는 **2안(신청만 리셋)** — 고객사 선택 (질의 Q-25) |

## 3. 상태 정의

### 3-1. 화면에 표시되는 상태값 (기존 값만 사용)

| 구분 | 값 | 표시 위치 |
|---|---|---|
| 신청상태 | 미신청 / 신청완료 | 학생 논문신청 목록 |
| 제출상태 | 미제출 / 제출완료 | 학생 학위논문제출 목록 (최신 차수) |
| 심사결과 | - / 합격 / 조건부합격 / 불합격 | 학생 학위논문제출 목록·상세, 교수·관리자 학위논문심사 |
| 평가 상태 | 위원: [임시저장](반복 가능) → [제출](수정 불가) / 위원장 현황표: 미제출 위원 '대기', 제출 위원은 점수 | 교수 심사 상세 |

### 3-2. 심사 건 상태 (S0~S7) — 서로 겹치지 않고, 모든 경우를 포함

| 상태 | 판별 조건 | 신청상태 (1안 / 2안) | 학위논문제출 최신 행 |
|---|---|---|---|
| **S0** 신청 전 | 이 단계 신청 이력 없음 (또는 철회로 삭제) | 미신청 | 없음 |
| **S1** 제출 대기 | 신청함, 이번 차수 미제출, 같은 신청 안에 심사 내역·결과 없음 | 신청완료 | N차 제출 · 미제출 |
| **S2** 심사 대기 | 제출함, 심사 내역 없음 | 신청완료 | N차 제출 · 제출완료 · 결과 - |
| **S3** 심사 중 | 제출함, 심사 내역 1건 이상(임시저장 포함), 결과 전 | 신청완료 | N차 제출 · 제출완료 · 결과 - |
| **S4** 합격 | 결과 합격 (종료) | 신청완료 | 합격 |
| **S5** 보완 제출 대기 | 이전 차수 조건부합격, 다음 차수 미제출 | 신청완료 | N+1차 제출 · 미제출 |
| **S6** 불합격 · 같은 학기 | 불합격 처리된 학기 = 현재 학기 | 신청완료 / **미신청** | 1안: N+1차 제출 · 미제출 / 2안: 불합격 |
| **S7** 불합격 · 다음 학기 이후 | 현재 학기 > 불합격 처리된 학기 | 신청완료 / **미신청** | 1안: N+1차 제출 · 미제출 / 2안: 불합격 |

- **S2′ / S3′**: 같은 신청 안에 결과가 확정된 차수가 있는 상태의 심사 대기·심사 중 (조건부합격 보완 제출 후, 또는 1안의 불합격 후 다음 차수 제출 후). R2에 따라 철회 불가
- 2안에서 불합격 후 다시 신청하면 **새 신청**이므로 S1·S2(철회 가능)로 돌아감

## 6. 재심사 경로 (위 기능의 조합)

| 경로 | 순서 | 신청 | 다시 심사하는 위원 | 철회 |
|---|---|---|---|---|
| **조건부합격 보완** | S3 → F10 조건부합격 → S5 → F4 → S2′ → F9 → F10 | 없음 (같은 신청) | 위원장이 지정한 위원(전체 또는 1명) 평가 후 위원장 판정 | 불가 |
| **불합격 1안 (신청 유지)** | S3 → F10 불합격 → S6 → (다음 학기) S7 → F4 → S2′ → F9 → F10 | 없음 (같은 신청, 지정 제출기간에 제출) | 관리자가 기존 화면에서 배정(F7) | 불가 (같은 신청에 불합격 결과가 있음) |
| **불합격 2안 (신청 다시)** | S3 → F10 불합격 → S6 → (다음 학기) S7 → F1 → S1 → F4 → S2 → F9 → F10 | 필요 (신청 내역만 리셋, 심사 내역 보존) | 관리자가 기존 화면에서 배정(F7) | 새 신청이므로 S1·S2에서 가능 |

| 비교 | 1안 | 2안 |
|---|---|---|
| 장점 | 신청이 리셋되지 않아, 세부단계가 여러 개일 때 **통과한 세부단계의 심사 내역이 그대로 유지** | 다시 신청하는 절차가 남아, 재심사 의사를 학생이 명시 |
| 고려 사항 | 불합격 후 2차는 철회할 수 없음 (요구서 예시 '본심사 2차 철회 시 1차 결과 유지, 2차 제출 버튼 활성화'와 다름) | 신청상태는 '미신청'인데 심사 내역은 남아 있어 **오류처럼 보일 수 있음** |

- 모든 경로가 같은 심사 건의 다음 차수로 표시되고, 이전 차수 기록(파일·평가·판정·총평)은 보존
- 판정 결과에 따른 분기는 1차 심사와 같음 (반복 횟수 제한 기능 없음)

## 8. 시연 시나리오 (상태 1개당 1개)

학생 화면 상단 '목업 시연' 바에서 **시나리오**와 **재심사 안**(1안/2안)을 고릅니다. 공통 배경: 논문작성계획서 합격(S4), 본심사 미신청(S0).

| 시나리오 | 상태 (예비심사) | 확인 포인트 | 재심사 안 영향 | 바로가기 (`/student-v3/student-dashboard?…`) |
|---|---|---|---|---|
| ① 신청 후 미제출 | S1 | 철회 → 요구서 문구 | 없음 | `screen=thesis-application&scenario=applied&detail=prelim` |
| ② 제출 완료·심사 전 | S2 | 상세에 [제출취소] 없음, 철회 → 제출 내역 문구 | 없음 | `screen=thesis-application&scenario=submitted&detail=prelim` / `screen=thesis-submission&scenario=submitted&view=prelim` |
| ③ 심사 내역 저장됨 | S3 | 철회 불가 | 없음 | `screen=thesis-application&scenario=reviewing&detail=prelim` |
| ④ 불합격·같은 학기 | S6 | 1안: 2차 [제출] 차단 / 2안: [관리] 신청 차단 | 있음 | `screen=thesis-submission&scenario=fail-same&plan=1` / `screen=thesis-application&scenario=fail-same&plan=2` |
| ⑤ 불합격·다음 학기 | S7 | 1안: 신청완료 + 2차 [제출] / 2안: 미신청 + [관리] 재신청 | 있음 | `screen=thesis-submission&scenario=fail-next&plan=1` / `screen=thesis-application&scenario=fail-next&plan=2` |
| ⑥ 조건부합격 후 보완 | S5 | 신청 없이 2차 제출, 철회 불가 | 없음 | `screen=thesis-submission&scenario=conditional&form=final` |

교수: `/professor-v3/professor-dashboard-proposal?screen=review&detail=RA_RETRY_002&view=chair` (2차 심사 + 이전 차수 조회), `…&detail=RA_TEST_CHAIR&view=chair` (판정)

## 9. 목업으로 확인하지 않는 것 (정의 범위 밖)

- 화면 간 데이터 연동 (교수 판정 → 학생 화면 반영): 학생 화면은 시연 바로 상태를 재현
- 교수·관리자 화면의 1안/2안 차이: 교수·관리자는 목록 1행 + 상세 이전 차수 조회로 두 안이 같음
- DB View 값 변경, 지도교수 변경 반영, 철회 시 심사일정 처리: 기능정의서 질의
- 한 기본단계에 세부단계가 여러 개인 경우의 부분 보존: 목업은 기본단계당 세부단계 1개 (1안 장점은 문서로 설명)
