# Auto Workflow Skill

## 목적
사용자 명령 한 번으로 전체 개발 사이클 자동 실행:
1. 탐색 & 계획 수립
2. 승인 요청
3. 코드 구현
4. 자동 알파테스트
5. 최종 보고

**핵심**: 사용자는 초기 요청과 승인만 하면, 나머지는 전부 자동

---

## 사용 시점

### 자동 감지 (권장)
사용자가 다음과 같은 개발 요청을 하면 자동으로 workflow-manager 실행:
- "○○ 기능 추가해줘"
- "△△ 버그 수정해줘"
- "××를 ◇◇로 변경해줘"
- "□□ 화면에서 ☆☆ 에러 고쳐줘"

### 수동 호출
명시적으로 workflow 모드 요청:
- "workflow로 ○○ 해줘"
- "자동 워크플로우로 진행해줘"
- "/workflow ○○"

---

## 실행 절차

### Step 1: workflow-manager 호출
```
Use workflow-manager subagent with user request: [사용자 요청]
```

workflow-manager가 전체 사이클을 자동으로 관리합니다.

### Step 2: Phase별 자동 진행

```
[Phase 1: 탐색 & 계획]
- 실제 파일/함수/변수 확인 (추측 금지)
- 계획 문서 작성
- 성공 조건 정의
- 사용자 승인 요청 ⏸️

[User: "진행"]

[Phase 2: 구현]
- 코드 수정 (자동)
  ↓
[Phase 3: 알파테스트]
- alpha-tester 자동 실행 (자동)
- 3회까지 자동 수정-재테스트
  ↓
[Phase 4: 최종 보고]
- 한글로 요약 리포트
- 커밋 제안
```

### Step 3: 결과 전달
workflow-manager의 최종 보고를 사용자에게 그대로 전달

```

📝 수정 내역:
  • board.js:390 - getCurrentUser() 제거하고 전역 변수 사용
  • board.js:448 - currentUser null 체크 추가

🧪 알파테스트 결과:
  • 시도: 2회
  • 결과: ✅ 모든 테스트 통과
  • 파일: test-professor-board.py

🎯 성공 조건:
  "교수 자료실 화면에서 '글쓰기' 버튼 클릭 시
   에러 없이 작성 화면이 정상 표시됨"
  ✓ 달성

커밋하시겠습니까?
```

### 실패 시
```
⚠️ 작업 부분 완료

[기능명] 구현은 완료했으나 테스트에서 문제 발견

📝 수정 내역:
  • [수정 내용]

⚠️ 알파테스트 결과:
  • 3회 시도 후 실패
  • 남은 문제: [한글로 설명]

🔍 추가 조치:
  1. [조치 사항 1]
  2. [조치 사항 2]

다음 선택:
  - HTML 파일도 확인해줘
  - 현재 상태로 커밋
  - 다른 방법 시도
```

## 사용 예시

### 예시 1: 버그 수정 (전체 자동)
```
사용자: "board.js에서 getCurrentUser 에러 수정해줘"

Claude (auto-workflow skill):
  → workflow-manager 호출

workflow-manager:
  [Phase 1: 탐색 & 계획]
  📋 getCurrentUser 에러 수정 계획

  현황: board.js:390에서 존재하지 않는 메서드
  목표: 글쓰기 버튼 클릭 시 정상 작동
  계획:
    1. getCurrentUser() 제거
    2. 전역 currentUser 사용

  진행하시겠습니까?

사용자: "진행"

workflow-manager:
  [Phase 2: 구현] - 자동
  [Phase 3: 알파테스트] - 자동, 2분 소요

  [Phase 4: 최종 보고]
  ✅ 작업 완료
  수정: getCurrentUser() 제거
  테스트: 2회 시도 후 통과

  커밋하시겠습니까?

사용자: "커밋해줘"

Claude: [커밋 완료]
```

### 예시 2: 새 기능 추가
```
사용자: "학생이 파일 다중 업로드할 수 있게 해줘"

Claude (auto-workflow):
  → workflow-manager 호출

workflow-manager:
  [Phase 1: 계획]
  📋 다중 파일 업로드 기능 추가 계획

  현황: 현재 단일 파일만 가능
  목표: 여러 파일 동시 선택 및 업로드
  계획:
    1. input[type=file]에 multiple 속성
    2. 파일 목록 표시 UI
    3. 업로드 로직 수정

  진행?

사용자: "좋아"

workflow-manager:
  [자동 구현 + 테스트]

  ✅ 완료
  테스트: 통과

  커밋?
```

### 예시 3: 3회 실패 케이스
```
사용자: "modal이 안 뜨는 버그 고쳐줘"

workflow-manager:
  [계획 → 승인 → 구현 → 테스트]

  ⚠️ 부분 완료

  구현: 완료
  테스트: 3회 실패
  문제: HTML에 모달 컨테이너 누락

  조치:
    1. HTML 파일 확인 필요
    2. 모달 div 추가

사용자: "HTML도 확인해줘"

workflow-manager:
  [새 사이클 시작]
  [HTML 탐색 → 계획 → ...]
```

## 통합 워크플로우

### 일반적인 흐름
```
1. 사용자 요청
   "○○ 해줘"
   ↓
2. auto-workflow skill 감지
   → workflow-manager 호출
   ↓
3. workflow-manager 동작:
   Phase 1: 탐색 & 계획 → 승인 요청 ⏸️
   Phase 2: 구현 (자동)
   Phase 3: 알파테스트 (자동)
   Phase 4: 최종 보고
   ↓
4. 사용자에게 결과 전달
```

### 사용자 개입 지점
1. **Phase 1 후**: 계획 승인
2. **Phase 4 후**: 커밋 여부 (선택)
3. **실패 시**: 추가 조치 선택

**그 외 모든 과정은 자동**

---

## 주요 기능

### 1. 추측 금지 탐색
- 모든 파일명/함수명 실제 확인
- Read/Glob/Grep 적극 활용
- 가정하지 않고 코드 읽기

### 2. 계획 우선
- 구현 전 반드시 계획 수립
- 성공 조건 명확히 정의
- 사용자 승인 필수

### 3. 한글 보고
- 비개발자도 이해 가능
- 기술 용어 최소화
- 사용자 관점의 성공 조건

### 4. 자동 연결
- Phase 2→3→4 자동 진행
- 중간 명령 불필요
- 사용자 개입 최소화

### 5. 실패 안전
- 최대 3회 자동 수정
- 실패 시 상세 리포트
- 추가 조치 사항 제안

---

## 주의사항

### 제한 사항
- workflow-manager는 한 번에 하나의 작업만 처리
- Phase 1 승인 없이는 구현 불가
- alpha-tester 최대 3회 제한

### 권장 사항
- 명확한 요청일수록 효과적
- 복잡한 작업은 단계별로 나누기
- 실패 시 추가 정보 제공

### 성능 고려
- Phase 1: 1-2분 (탐색 + 계획)
- Phase 2: 1분 미만 (구현)
- Phase 3: 2-5분 (알파테스트, 최대 3회)
- 총 소요: 평균 4-8분

---

## 성공 조건

다음 중 하나가 되면 워크플로우 완료:
1. ✅ 구현 + 테스트 전부 성공
2. ⚠️ 구현 완료 + 테스트 실패 (추가 조치 제안)
3. ❌ Phase 1에서 사용자 취소

## 관련 도구

- **workflow-manager agent**: 전체 워크플로우 관리
- **alpha-tester agent**: 자동 테스트-수정

## 사용 팁

1. **명확한 요청**
   - ✅ "board.js에서 getCurrentUser 에러 수정해줘"
   - ❌ "뭔가 안 돼"

2. **단계별 진행**
   - 큰 작업은 단계로 나누기
   - 예: "파일 업로드 기능 추가" → "UI 추가" + "로직 구현"

3. **실패 시 협력**
   - 추가 정보 제공
   - 다른 방법 시도
   - 수동 확인 병행
